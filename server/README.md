# SillyDraft 个人远程执行器

可选的 Dart 服务，用来让正文生成、资料提取、候选走向和生图在手机离开应用后继续执行。本地阅读、编辑和直连模型无需启动此服务。手机若要直接使用桌面上的作品库，用应用内的“设置 → 手机连接”，不需要本服务。运行环境与应用一致：Dart 3.13.5。

## 启动

在 `server/` 下执行 `dart pub get`，复制 `model-profiles.example.json` 为 `model-profiles.json`，删除不用的示例配置，填写实际模型地址和名称。每个配置的 `id` 是客户端选择的模型 ID；`model` 才是上游模型名称。

```sh
dart pub get
cp model-profiles.example.json model-profiles.json
# 用密码管理器或部署平台设置环境变量，不把密钥写进配置或提交到仓库。
dart run bin/sillydraft_server.dart --config model-profiles.json
```

运行前须设置 `SILLYDRAFT_RUNNER_TOKEN`，至少 16 字符，建议使用随机生成的长令牌。若配置使用 `apiKeyEnv`，还须设置该名称对应的上游 API key；本地免鉴权模型可省略该字段。配置拒绝直接嵌入 `apiKey`。密钥不会保存到任务数据库。

默认监听 `127.0.0.1:8787`，数据保存在 `runner-data/`。参数：`--host`、`--port`、`--data`、`--max-concurrent`（默认 2，范围 1–16）。同一个数据目录只能运行一个进程。使用系统进程管理器运行；SIGINT/SIGTERM 会保存中断状态并关闭服务。意外崩溃后由管理员重启服务，任务本身不会自动重新付费生成。

手机访问时通过 HTTPS 反向代理连接到本服务。也可在可信局域网明确绑定局域网地址，并在客户端启用 HTTP；HTTP 会明文发送令牌与创作内容。此服务是单人共享令牌模型，不提供多租户账号、计费或公开注册。知道令牌的人能够查询、提交、取消此服务中的所有任务。

## 客户端设置

设置 → 添加连接 → 连接方式选择 **SillyDraft 远程执行器**。地址填写服务根地址（不加 `/v1`），访问令牌填写 `SILLYDRAFT_RUNNER_TOKEN`，模型名称填写配置 ID，例如 `writer`。可以点击“检查连接并获取模型”选择已配置的 ID。客户端上下文与输出上限应与服务端配置一致；上游支持的额外采样参数在服务端 `extraParameters` 中明确开启。

把此连接分配给正文写作、资料整理或插画生成。编辑 Agent 的工具在客户端执行，因此编辑 Agent 角色需要另一个 OpenAI 兼容直连模型；它委派的正文任务可使用远程连接。

ST 角色卡、预设、宏、世界书、正则和分支筛选仍由客户端核心编译器执行。服务只收到冻结后的模型请求与明确选中的参考图片，不上传整个书库，也不接管编辑工具。模型原始输出回到客户端后才执行输出处理、创建待审阅候选；采纳时再次检查正文版本。

## 断线、取消与恢复

- 关闭应用或中断 HTTP 连接只会断开本地观察，服务端任务继续执行。
- 重新打开任务页，点击 **获取远程结果**，使用原任务 ID 查询状态和结果。该动作仅 GET，服务端找不到任务时会报错，绝不会创建另一笔请求。
- **重新生成（新任务）** 使用新 ID，并重新请求上游模型，可能产生新的费用。
- **取消生成** 向服务端发送取消指令；只有收到确认才在本地记为已取消。网络或鉴权失败会显示错误，不假装远程已经停止。上游收到取消前已完成的工作可能仍计费。
- 服务进程重启后，原本排队或执行中的任务变为 `interrupted`，保留部分输出。没有可靠的上游恢复协议，因此不会自动重试。
- 取回旧版本对应的正文候选后，若作者已改写正文，直接采纳会触发版本冲突。插画仍可保存，并显示其依据版本已过期。

## 接口与持久化

所有接口使用 `Authorization: Bearer <token>`，不接受重定向。返回 JSON 不包含上游地址、密钥或输入快照。

| 请求 | 行为 |
| --- | --- |
| `GET /v1/models` | 列出配置 ID、名称和上下文/输出上限 |
| `POST /v1/jobs` | 提交 `{id, profile, kind, request, references?}`；新任务 202，同 ID 同内容返回已有任务；同 ID 改输入返回 409 |
| `GET /v1/jobs/{id}` | 返回状态、累计正文/推理摘要、完成信息与时间戳 |
| `DELETE /v1/jobs/{id}` | 请求停止；已完成任务返回 409，供客户端取回结果 |
| `GET /v1/jobs/{id}/image` | 已完成图片的受鉴权二进制输出 |

`kind` 为 `text` 或 `image`。文本请求使用核心 `ProviderRequest.raw`；图片使用 `ImageRequest.raw`，参考图片为 `{mimeType, data}`，其中 `data` 是 Base64。客户端的 `executionId`/取回控制字段不发送为上游请求参数。

SQLite WAL 保存输入、上游配置快照、进度与结果。执行中的输出与输入分开保存，每 0.25 秒最多落盘一次，查询总是返回已收到的全部输出；完成、失败、取消或正常停止服务时保存全部输出，进程被强制结束（如 SIGKILL、断电）时可能丢失最后一次落盘后收到的少量输出。数据目录为数据版本 2：新版执行器首次启动时自动升级版本 1 的数据（只新增一张表），之后旧版执行器会拒绝打开并提示升级。任务 ID 与完整输入指纹保证重复 POST 不会重复执行。数据库包含创作内容，服务所在主机的磁盘加密、备份和访问控制由部署者负责。

边界：最多 1,000 个保留任务、64 个待处理任务、默认 48 MiB 请求体；文本/推理摘要各最多 1,048,576 个字符；图片最多 32 MiB，参考图片最多 4 张。累计资料达到约 1 GiB 后停止接收新任务；已在执行的文本仍受单任务输出限制。服务端只允许管理员配置的上游地址及 `imageDownloadHosts`，客户端无法新增下载主机。

任务不会自动过期，以免离线设备失去尚未取回的结果。容量满时，在确认客户端已取回所需结果后，停止服务、备份数据目录，再使用 SQLite 管理工具删除确认不要的终态任务并执行 `VACUUM`。被删除任务无法再取回；不要更改仍需取回任务的 ID、输入或状态。备份应在服务停止后复制整个目录。

## 验证

```sh
dart analyze
dart test --reporter expanded
```

测试使用本地模拟 HTTP 服务，覆盖鉴权、同 ID 重复投递、取消确认、手机断线后继续执行、旧正文冲突、图片传输与本地保存、缺失任务不重提，以及真实子进程 SIGKILL 后恢复。没有调用付费模型。Windows 跳过 Unix 信号用例，HTTP 与持久化测试仍可运行。
