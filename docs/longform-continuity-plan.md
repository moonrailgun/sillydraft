# 长篇连续性改进与复测

2026-11-06。用户要求实际继承 InkOS 的有用能力，并反复评分到接近或超过。
旧评测及其当时的“不改产品”决定保留；本次是新的实现与确认实验。

## 实现范围

参考固定 InkOS `53adac4e974b54dafda975edc4edd07cad364c18` 的章前规划、增量状态结算与正文核对思想，独立实现，不复制代码或提示词。

1. 复用资料版本系统。未结伏笔进入候选上下文，预算不足时仍可移除并记录原因；不把全部伏笔强制钉住导致长篇无法生成。
2. 旁路整理增加有界批量读取，保留共享工具循环的 12 次调用安全上限。新任务写 fact 必须引用当前冻结正文的原句；引文随版本来源保存。旧任务保持原有协议。此检查证明引文存在，不冒充语义蕴含验证。
3. 内置小说预设启用一次章前规划：只使用冻结的输入，形成带原文依据的事实约束、场景因果和已有伏笔安排。计划是建议，不是事实；不入正文或资料库。准备/预览不调用模型，执行时保存计划和最终请求，审读复用同一请求。规划失败保留原请求。外部 ST 预设不默认加入规划；远程、MVU、文本补全和局部改写不启用。
4. 更新任务详情、预览说明、兼容文档和有意义的回归。保持正文采纳的版本检查与现有审读边界。

影响路径：WritingService、TaskRunner/quality、lore_context、SidecarAgent/runner；资料选择、旁路、写作协议测试；任务和写作预览 UI；benchmark 入口继续调用真实生产流程。

## 新实验（生成前冻结）

- 输入：`tool/novel_benchmark/fixtures-continuity.json`，两个新故事，每篇 16 章，每章目标 2000 汉字；开发集 `projection`，确认集 `bindery`。
- 写作模型、温度与评委沿用旧实验。比较完整工作流，不宣称等计算量。
- 每篇生成 InkOS、冻结基线 SillyDraft、改进版 SillyDraft。开发集用于诊断和迭代；确认集评分直到开发版冻结后才查看。
- 评委 Gemini 和 Astra 各评两种 A/B 排序。使用现有八维等权评分、原文引文校验；每个失败单元最多三次，经诊断才补跑，保留全部尝试。
- “接近”：每位评委的两种排序均值中，连续性/因果/伏笔回收的三维均值差和总分差均不低于 InkOS 0.3 分。先在开发集达标，再在确认集验证。同样报告各单维、排序差和未修改基线波动；缺少有效平衡评分不算达标。
- 每轮记录版本、所有分数、失败及成本；只针对核验后的问题改进，不改输入或降低达标门槛。
- 本地单元测试不调用真实模型；另行授权的 benchmark 使用本机 Magpie。
- 不承诺有限轮次必然胜出；若供应商不可用或重复迭代无改善，明确报告实测边界。
