# SillyDraft 系统与设计规范

本文件是 SillyDraft 的系统概览与统一规范入口，适用于产品设计、界面修改、功能开发和验收。整理日期：2026-10-24。规则来自现有产品文档、共享组件、核心实现及仓库约定；具体协议映射、操作步骤和平台构建流程仍由对应专题文档维护。

历史设计稿中的“现状”和验证记录描述的是当时状态，不能直接视为当前行为或本次验证结果。本文按整理时的实现归纳；行为变化时，应同步更新本文及相关专题说明。

## 1. 系统定位

SillyDraft 是一个**本地优先、移动端优先的小说创作与阅读工作台**，以作品为中心，把正文、阅读、编辑助手、故事资料、插画和分支管理放在同一条创作流程中。目标平台包括 Android、iOS、macOS、Windows 和 Linux，具体原生能力按平台声明支持范围。

- 作者可以离线阅读、编辑、管理资料和备份，不强制登录；模型能力通过作者配置的连接提供，本地示例模式必须明确标识。
- 编辑器负责写作，阅读器负责连续阅读；助手通过有边界的工具操作作品，模型生成、正文版本、故事资料和任务记录可追溯。
- ST 角色卡、预设、世界书、正则和社区前端是重要的资源生态。SillyDraft 与 SillyTavern 没有直接隶属关系；ST 是兼容标准之一。
- 分支代表不同故事走向；章节版本、变量和资料都必须尊重当前分支及故事位置，不能把未来情节或另一分支的信息带入当前上下文。

主要能力包括书架与作品管理、富文本编辑、沉浸阅读、编辑 Agent、ST 资源管理、MVU 变量、人物与设定资料、关系图与地图、插画、版本与分支、迁移备份、远程作品库和可选远程执行器。

## 2. 架构与数据原则

| 层次 | 职责与边界 |
| --- | --- |
| Flutter 界面 `lib/` | Riverpod 状态、Forui 组件、Quill 编辑器和平台服务；按 `features/<领域>/` 划分，由 `app/services.dart` 组装依赖 |
| 纯 Dart 核心 `packages/sillydraft_core/` | 存储、版本、分支、ST 导入与编译、模型协议、任务、MVU、HTML 块、资产、迁移及远程协议；不依赖 Flutter |
| 可选执行器 `server/` | 持久化并执行客户端冻结的模型请求；ST 编译和输出处理仍在客户端 |

- 能放在核心的业务逻辑放核心，通过 Dart 测试验证。界面复用核心规则，避免出现两套采纳、版本或兼容语义。
- 一个作品库使用一个 SQLite（drift）数据库。`StoryRepository` 是一个 library，各领域存储方法使用 `part` 文件中的 extension。
- 正文使用 Quill delta（`ManuscriptContent`）；`revisions` 不可变，`branch_chapters` 将分支内章节指向当前 revision。编辑和恢复历史都创建新 revision，不覆盖旧历史。
- 模型输出内部先保存为 proposal，再写成正文 revision。写作任务默认自动采纳；常规界面不要求作者逐次审阅“候选”。正文或变量版本冲突时保留为“未写入的正文”，由作者处理。
- 采纳必须检查 `baseRevisionId` 和变量版本，不能覆盖生成期间发生的修改。正文、变量和相关引用的变更应保持事务一致性。
- 生成任务持久化编译请求、预设、宏值、时钟、种子、显示正则等完整输入快照。失败、取消、重试和费用记录必须能关联到实际执行。
- 删除编辑会话不删除作品正文。作品先归档再删除；导入、恢复和迁移先校验格式与引用，失败不能留下部分写入或损坏现有作品库。

## 3. 信息架构与自适应布局

- 全局入口为“作品、资源、设置”：桌面使用侧栏，手机使用底部导航，切换时保留各页面的筛选和滚动状态。编辑助手属于作品，不单独成为全局创作空间。
- 作品工作区在窄屏提供“正文、资料、助手、插图”四个分区；宽屏采用目录、正文阅读区域、工具区域的布局。当前主界面与工作区以 **900 个逻辑像素**作为宽屏切换点，新增布局沿用现有判断。
- 宽屏右侧工具入口使用图标与提示，切换助手、资料或插图时保持中央正文稳定；目录选中项与阅读章节双向同步。
- 左右面板可独立收起，拖动分隔线调整宽度并持久化；保留键盘操作能力。窄屏与宽屏之间切换不能丢失正在编辑的内容。
- 书名下显示当前分支并提供切换；独立阅读器有明确入口。手机从工作区其他分区返回时先回到正文，再退出作品；宽屏返回可直接退出工作区。
- 编辑器内的助手在宽屏停靠，在手机使用底部面板，同时保留正文语境。宿主统一管理标题和导航，嵌入式页面不重复显示一套顶栏。
- 遵守安全区域、键盘避让和系统文字缩放。最外层负责键盘高度调整，嵌套脚手架不重复扣减；小屏内容和操作必须可滚动、可访问。
- 书架使用真实作品信息：封面下标题最多两行；简介、类型等可选字段没有内容时不显示空占位。

## 4. 视觉与共享组件

### 4.1 主题、字体和图标

- 应用界面沿用 Forui neutral 明暗主题，通过 `context.theme.colors` 和 `context.theme.typography` 取色与字体；Material 桥接主题由同一套主题派生，避免独立配色。
- 应用字体使用 Inter，并保留 PingFang SC、Hiragino Sans GB、Microsoft YaHei、Noto/Source Han 等中文字体回退；阅读器使用独立的阅读样式设置。
- 图标统一使用 `FLucideIcons`。图标按钮复用 `IconAction`、`HeaderIconAction`，提供 tooltip 与语义标签，不能只依赖图形传达动作。
- 开关的关闭、悬停、开启状态均须可辨认。颜色、边框和选中背景应表达状态，不能因深浅主题切换而失去辨识度。
- 复用现有主题与共享组件的触控、焦点和悬停行为，不在各页面重新实现一套控件风格。

### 4.2 相邻元素必须留白

**独立元素之间不得直接贴在一起。** 按钮、消息气泡、卡片、图片、输入框及操作区，无论横向还是纵向排列，都必须有清晰可见的外部间距；不能因为采用紧凑布局或面板变窄就取消留白。

- 同组独立控件之间默认留 **8 个逻辑像素**；按钮与消息卡片、图片与操作区等独立内容块之间默认留 **12–16 个逻辑像素**。优先复用所在页面一致的间距，不使用零间距。
- 内边距、圆角露出的背景、边框或背景色差不能代替元素之间的外部间距。
- 间距由父布局或相邻元素的一侧统一提供，避免重复叠加；条件显示、流式追加内容和自动换行后也必须保留。
- 分段控件等有意连成整体的组件可在内部相接，但整个组件与外部独立元素仍须留白。

已反馈的反例：2026-10-24，编辑助手生成插画后，“全部插入正文”按钮底边与下一条“编辑助手”完成消息卡片顶边直接贴合。两者是独立内容块，必须保留 12–16 个逻辑像素的垂直间距；消息卡片自身的内边距不算两者之间的留白。

### 4.3 弹窗、面板、列表和反馈

- 弹窗使用 `showAppDialog` / `AppDialog`，简单确认与单行输入复用 `confirmAction` / `askText`；底部面板使用 `showAppSheet` / `AppSheet`。
- 弹窗取消操作在前、主要操作在后，操作行可换行并保留间距，正文可滚动；不让长内容把确认或关闭入口挤出可访问范围。
- 菜单、选项标签、侧栏、底部导航分别复用 `MenuAction`、`ChoicePill`、`AppSidebar`、`AppBottomBar` 等现有组件。侧栏的图标与文字共同表达选中和悬停状态，底部操作保持可达。
- 轻量反馈使用 `toast`，错误使用 `showError` 等统一入口。错误说明应能帮助作者重试或处理，不把失败伪装成成功。
- 异步页面复用 `AsyncView` 等组件：首次加载、刷新、空状态和失败分别表达，刷新时保留已有数据，失败提供重试入口。
- 计数徽标为零时隐藏。未写入正文与正在运行的任务应有可定位的入口，不用永久占位增加噪声。
- 助手等待期间尚无正文或错误时，使用紧凑的状态行与“查看任务”入口；避免空的大消息卡片。状态文字在窄面板内可收缩，不挤掉操作入口。

组件依据：[共享组件](../lib/app/widgets.dart)、[主题](../lib/app/theme.dart)、[工作区](../lib/features/editor/workspace_screen.dart)。

## 5. 编辑、阅读与正文显示

### 5.1 编辑和章节

- 编辑器自动保存，保留显式保存快捷键、撤销和历史恢复。异步操作不能静默覆盖当前未保存内容。
- 章节名称与自动章节编号分开存储和展示。序章等可不参与编号；重命名只修改名称，目录、编辑器、阅读器与导出保持一致的显示规则。
- 同章“续写”追加正文；“重新生成”从上一章末尾重新写，本章旧正文、变量和资料不进入模型上下文。等待和思考阶段保留旧正文，新正文开始输出后阅读区切换到新内容。替换内容成功生成并通过版本检查后才写入，旧版本留在历史中；失败、取消和冲突保留原正文。
- 写下一章时可复用尚未成功生成的空末章，避免重试不断制造空章节。流式进度在当前阅读语境中展示，完成后自动写入。

### 5.2 阅读体验

- 阅读器独立于编辑器，提供连续阅读、目录、书签、搜索、全书进度、键盘翻页和自动滚动等入口。
- 字体、字号、背景、亮度、行距、段距、字间距、页边距、首行缩进及两端对齐按阅读设置生效；标题、列表、引用等结构保留各自排版。
- 阅读主题独立于应用主题，支持六种背景与夜间设置。正文和对话颜色沿用现有对比度校准，强调和斜体仍需可读。
- 阅读位置、书签和搜索命中必须落回正式正文的位置，不能依赖一次渲染产生的临时偏移。
- 章末走向建议按正文版本生成并提供刷新、重试；使用资料模型的能力与成本应可理解。独立阅读界面不展示内部推理、调试日志或待处理候选列表。
- 走向推荐理由要求一句、30 字以内，只点出最关键的依据，不复述剧情或逐项比较；界面最多显示两行，超长省略，方便快速扫读。

### 5.3 正式正文与显示投影

- 存储、导出和模型上下文始终使用正式正文；显示正则、富文本排版和 HTML 渲染不能反写正文。
- `ManuscriptPresentation` 是一次性的显示投影，并维护显示偏移到原文偏移的映射。
- **当前分支的阅读器使用分支当前显示正则**，修改规则后可立即重新显示既有章节；有生成任务时，宏环境仍来自任务冻结快照。未指定分支的历史版本投影与 proposal 预览在有关联任务时使用任务冻结规则；无关联任务的正文使用分支规则，proposal 保持原文显示。
- 原文/显示效果切换仅影响展示。具体行为以 [proposal_store.dart](../packages/sillydraft_core/lib/src/storage/proposal_store.dart)、[display_store.dart](../packages/sillydraft_core/lib/src/storage/display_store.dart) 和 [ST 兼容说明](st-preset-compatibility.md) 为准。
- `ReaderDocument` 拆分段落，`HtmlBlocks.find` 识别 HTML 块，`ProseMarkup` 按 ST `messageFormatting` 处理对话引号、强调和隐藏标记。

## 6. 助手、生成任务与使用量

- 自动采纳的写作任务在定稿前自动审读，最多进行一轮局部修订和一次复查；仅采用通过复查的修订稿，失败时保留原稿并在任务中说明。仅允许替换审读引用的原句，每处原句最多 200 字、替换正文最多 400 字，越界时保留原稿。沿用写作连接和接口类型，额外调用最多三次，不循环重试；取消和正文／变量版本保护仍生效。资料整理只读取最终采纳的正文。首版跳过远程执行、MVU 及含 HTML、宏或代码围栏的输出；上下文超限或模型不能返回有效结构时保留原稿。
- 正文、编辑、资料、插画分别配置模型职责，同一连接可以提供多个模型。改变写作连接或模型后重新预览实际请求。
- 生成前的请求预览反映实际资源版本、编译内容和参数。预设能力按使用场景声明，不能假定所有 Agent 调用都等同于正文生成。
- 正文生成与编辑对话保持明确边界。普通写作工具每轮只允许一次成功写作；后续读取看到已写入版本，重复写作或源版本变化应明确拒绝。
- 助手应区分续写、完整重写和清理开场模板；意图不清时澄清，不能仅凭关键词覆盖已有故事。
- 同会话的请求按队列顺序执行，出队时取得最新上下文。停止或失败当前请求不应丢弃后续队列。
- 导航离开页面不取消任务；全局显示运行数量并可进入任务。退出应用时提示仍在运行的工作，屏幕常亮不能表述为后台持续运行保证。
- 本地中断与远程执行分开表达：本地任务不假装可自动续跑；远程“取回同一任务”与“重新生成”是不同动作，后者可能产生新的模型费用。
- 失败、取消与冲突保留已有产物，提供可理解的状态和处理入口；不得无提示地重试付费生成。
- Agent 上下文压缩保留系统约束、当前请求和完整工具调用/结果组；原记录与摘要分开保存，不修改冻结请求或正文。压缩失败及仍超限应明确报错，不能静默丢弃消息或无限重试。
- 技能采用目录、按需激活、按需读取的方式接入；格式、名称冲突和内置覆盖规则遵守 [Agent 技能规范](agent-skills.md)。本地技能文件不是可执行授权，脚本与二进制不因导入而执行；技能不随作品备份自动传播。

使用量遵守以下口径：优先采用服务端报告的费用，其次采用支持的模型价格估算；缺少价格时显示“无价格”，不能记成零或从统计中无声消失。估算 token 标记 `≈`，金额统一以 USD 表达，图表按本地日期统计。计量失败不阻塞创作；同一次远程执行按 executionId 去重。订阅模型的 API 等价估算不能说成实际账单。

## 7. 资源、预设与 ST 兼容

- **凡是 ST 已有定义的行为，都按 ST 的做法实现，不另起语义。** 固定基线为 SillyTavern **1.19.0 / `06bde939fb1e9c4c8d8641d810f0a916b5bce127`**；判断行为读该提交源码，在代码注释中注明依据，不用浮动分支替代。
- HTML 前端及接口对齐酒馆助手 JS-Slash-Runner，变量行为对齐 MVU（MagVarUpdate）。导入成功、文件格式兼容、提示词兼容和扩展运行兼容必须分别说明。
- 角色卡支持的 JSON、PNG、CHARX 等导入路径保留原文件与未知字段；导入有预览和诊断，相同资源按现有去重规则处理。未知宏、字段及未支持能力不能静默丢弃或冒充执行。
- 资源库编辑创建新版本；归档与删除分开，仍被引用的资源不能直接删除。作品分支的覆盖设置不修改资源原件或其他分支。
- 分支预设参数即时保存，切换后保留各自覆盖，提供重置和另存为新预设。作品菜单、助手标签和生成页复用同一套设置面板。
- 预设面板按“采样参数、提示词管理、预设正则、兼容提示”组织，只展示适用配置；长列表独立滚动并按需构建。提示词内置标记允许停用，不当作普通条目删除。
- 正则规则保留顺序和未知字段，开关仅改变启停；规则文本使用等宽、可换行、可选择复制的呈现，并保留 JSON 操作入口。
- 世界书共享一次编译的总预算；超限给出诊断和调整入口，所用预算随任务冻结。token 估算不能标成精确计数。
- 编辑助手的聊天预设开关按兼容说明生效；执行级工具约束不能被预设取消。正文可用的文本补全预设不等于编辑助手也支持，不能接受配置后静默忽略。
- 不自动采用导入预设中的代理地址、请求头或凭据。具体支持的宏、参数、模型协议及缺口由 [ST 兼容说明](st-preset-compatibility.md) 维护，行为变化时同步更新。
- 照搬外部标准的名单或规则要登记到[基线同步清单](../.claude/skills/sync-baselines/SKILL.md)，定期对照，而不是永久固定在某次复制结果上。

## 8. HTML 前端与变量安全

- Markdown 按 showdown 及 ST 选项解析；围栏结束遵守 showdown 规则，包括结束围栏同一行剩余内容继续作为正文。
- 含完整页面的围栏 HTML 是 frontend，在隔离网页视图中运行受支持的酒馆助手接口；行首原始 HTML 是 fragment，按 DOMPurify 规则净化，不获得这些接口。
- 前端只允许 HTTPS 联网，不允许任意页面跳转、读取本地文件、相机、麦克风、密钥或其他作品数据；不执行角色卡附带的脚本库。无法兼容的脚本与接口应给诊断。
- 前端没有直接调用模型的通用权限。受支持的输入提交通过宿主的写作流程执行，并受重复提交、忙碌状态和版本检查约束；`/send`、`/trigger` 等交互按兼容定义打开写作确认，不能将这些入口描述为任意模型调用。
- Android、iOS、macOS 使用原生网页视图；Windows/Linux 提供源码回退。用户关闭 HTML 渲染后仍应能够查看内容，不显示空白冒充支持。
- MVU 初始化、更新命令、schema、模板、状态数据及变量宏遵守已实现的兼容范围。变量按全局、聊天、楼层、角色、预设等作用域管理，历史恢复和重算不得跨越应有的分支、章节边界。

## 9. 人设、资料、关系与地图

- 作者人设可复用，默认“我”为本机人设；人设影响后续宏与请求，不回写已有正文。正在被绑定的人设不能直接删除。
- 人设表单的 AI 补全结果可编辑、可撤销，保存前仍由作者掌握；生成参考图前确认提示词，参考图数量遵守现有上限。
- 故事资料区分事实、计划和推测，记录来源章节/版本及过期状态。不能把模型推测写成已发生事实；历史章节和分支读取只获得当时可见资料。
- 人物、设定、组织、物品、地点、事件、伏笔等沿用统一资料体系。关系有方向，地图位置使用归一化坐标，避免分辨率变化导致位置漂移。
- 手动资料分析先提供建议供作者处理；自动旁路资料任务按已启用职责写入对应资料，保持与正文生成分离。
- 旁路任务的职责、模型和成本应可见，按章节来源校验版本；下一次写作按既有等待与超时流程处理前序资料更新，不能把过期资料伪装成最新资料。

## 10. 插画与资产

- 生图先确认提示词和参考图；一组插画集中确认后按顺序执行，不为每张重复同一轮确认。失败或取消停止后续生成，保留已完成图片，不静默重试。
- 提示词围绕可绘制的单一瞬间，说明人物状态、动作、空间、视角与光线；服装等状态优先采用当前剧情，未知外观读取资料，不能仅凭名字猜测。
- 不同供应商使用适合其模型的提示形式：NovelAI 使用英文标签，ComfyUI 按工作流/模型要求处理，未知约束时不伪造专用语法。
- 选段插画使用选中文本及必要的当前正文、资料，不混入旧聊天、无关预设或技能。工具权限限定在读取与生图所需范围；只有图片实际保存后才能报告生成成功。
- 图片生成后先进入图库，设置封面、地图底图或插入正文是独立操作。每张图片保存提示词、参考图、模型、来源位置与版本等可追溯信息。
- 助手生成图片上的插入和下载按钮在桌面端仅于悬停或键盘聚焦时显示；触屏端保持可见。
- 单张和批量插入都检查来源版本与插入位置，跳过已插入图片，不能凭猜测插到错误段落。批量定位失败不能留下半批写入；旧图片缺失位置时让作者选择。
- 生图失败不阻断正文编辑与阅读。图片、操作按钮、进度和后续消息之间遵守本规范的外部间距要求。

## 11. 本地、远程、备份与隐私

| 能力 | 数据与行为边界 |
| --- | --- |
| 桌面远程作品库 | 桌面 `RemoteHost` 通过 drift 协议共享现有数据库，手机 `RemoteSession` 连接它；不是另建一份同步副本 |
| 手动 HTTP 同步 | 传输加密完整快照，使用强 ETag 与条件 PUT；发生冲突保留双方副本，不盲目覆盖 |
| 个人远程执行器 | 执行冻结请求，断线后查询原任务；重新生成是新执行 |
| 扫码传输 | 按所选资源、人设、技能或连接显式传输；凭据有效期与单次使用限制按传输协议执行 |

- 远程作品库使用 TLS 证书固定和配对 token；版本不兼容时拒绝连接。重连保持仓库对象稳定，保留未提交编辑，并明确显示断连、只读或写入失败状态。
- 手机不能随意修改桌面的模型密钥；已保存凭据与已确认端点绑定，端点改变时不能自动把旧密钥发往新地址。本地订阅能力按桌面支持范围声明。
- 正文可导出 TXT、带图片的 Markdown 和 EPUB；完整迁移使用加密备份。导入前校验，受支持版本走已验证迁移，不支持的格式或数据库版本明确拒绝且不修改原库。
- 模型密钥与普通作品数据分离；普通备份和同步不带密钥。当前本地连接密钥在 `secrets.json` 中保存，不能宣传为已加密安全存储；扫码显式分享连接密钥时，在二维码上方明确提示。
- 默认“我”等本机身份与可共享的自定义人设按同步规则区分，人设参考图不能假定随作品同步完整传播。
- 读取、导出、联网和导入能力必须遵守各自的信任边界；错误不能泄露密钥或把内部诊断直接写进作品正文。

## 12. 工程、交付与验收

### 12.1 开发约定

- 文档与界面默认中文，代码与注释用英文。复用现有组件、服务、存储层和协议，不为同一行为增加并行实现。
- 基线为 Flutter **3.47.7** / Dart **3.13.5**。根目录、核心包和 server 分别维护锁文件，依赖安装使用 `--enforce-lockfile`。
- Flutter 界面运行 `flutter analyze`、`flutter test`；核心包和 server 分别运行 `dart analyze`、`dart test`。按改动影响选择验证，并完成仓库要求的检查；测试使用本地协议服务，不调用付费模型。
- 格式检查范围覆盖 `lib test integration_test test_driver tool packages/sillydraft_core/lib packages/sillydraft_core/test server/lib server/bin server/test`，命令见 [AGENTS.md](../AGENTS.md)。
- ST 对照数据由核心包 `tool/capture_st_reference.mjs` 在 Node 22 下从固定源码生成；先审查 reference JSON 差异，再运行 `dart test test/st_compiler_test.dart test/provider_test.dart`，不能为让测试通过而改基准。
- 调试运行中的 macOS 库时，只读打开 `~/Library/Application Support/com.moonrailgun.sillydraft/library.sqlite`；禁止直接写入运行中的数据库。正文查 `revisions.content_json`，生成快照查 `generation_tasks.input_json`。
- macOS 的 `FLTEnableImpeller=false` 用于规避中文字形噪点；修改后必须重新构建，热重载不能验证该设置。
- 除非用户明确要求操控电脑，否则不使用 Computer Use 控制用户电脑。

### 12.2 Git、PR 与发布

- 获授权提交后，按可独立交付、验证和回退的目的拆成原子提交；不同功能、缺陷、无关重构、格式化和清理分别处理，不能仅因属于同一需求就合并。
- 每个提交应用到父提交后都必须完整、可构建、可运行；不能依赖尚未提交的工作区内容或后续修复。一个功能必需的实现、调用方、测试和配置应在同一完整提交内。
- 拆分前检查完整 diff，列出分组；每次只暂存该组所需文件或代码块，提交前审查暂存 diff，保留用户和其他任务的改动。
- 验证针对每个提交实际包含的状态，不能用含有后续改动的工作区测试结果代替。纯文档改动检查内容、格式和链接。
- 提交与 PR 标题使用 Conventional Commits：`<type>(<scope>): <summary>`；type 小写，scope 简短小写，summary 简短、使用祈使语气、不加句号，如 `fix(reader): preserve spacing between actions`。**除非明确要求，不添加 PR 正文。**
- 发布遵守 [构建与发布说明](building.md)：版本、build 号和 tag 保持一致，由 `release.sh` 完成相应升版、提交、打 tag 和推送步骤；不能把普通修改或本地提交授权当作发布授权。
- CI 构建、签名、公证、商店发布与设备验证分别记录。自动更新按平台提供检查与手动下载安装，保留关闭自动检查的入口，不把下载等同于已安装。

### 12.3 验收标准

- 功能验收覆盖受影响的正常、空、加载、失败、取消、重试与冲突状态；与版本或持久化有关的改动检查旧数据和恢复路径。
- 界面修改检查所有相邻元素的可见边缘，确认独立控件和内容块不贴边；检查窄面板、长文字、换行、流式内容及条件显示后的布局。
- 检查深浅主题、文字缩放、键盘、安全区域、滚动和焦点可达性。只通过布局或功能测试不代表视觉验收通过，需要查看受影响状态的实际渲染结果。
- 真实网页视图只能通过原生路径验证，例如 `flutter test integration_test/html_render_test.dart -d macos`；普通 widget 测试不能替代网页运行、沙箱和平台桥接验证。
- 报告明确区分代码已接入、测试已通过、本地原生运行、远程 CI、发布和实际设备结果；历史截图与历史通过记录不能当作本次验证。
- 未覆盖的平台、原生能力及已知兼容缺口应明确列出，不静默省略，也不宣称完全兼容。
