# 使用 SillyDraft

## 界面总览

应用只有三个入口，桌面在左侧栏，手机在底部：

| 入口 | 用来做什么 |
| --- | --- |
| 作品 | 书架：新建、搜索、归档作品（已归档的可以删除），恢复备份、连接远端作品 |
| 资源 | 导入和管理角色卡、ST 预设、世界书和正则脚本 |
| 设置 | 外观、模型连接、每类任务使用哪个模型、世界书预算、用量与成本，以及版本号与检查更新 |

搜索、筛选和滚动位置会在入口之间保留。手机在资源或设置中按系统返回会回到作品。助手总是协助某一部作品，所以它在作品里，没有单独的入口；作品有未写入的正文（生成期间正文或变量有改动，结果没能自动写入）时，作品里助手的导航图标上会显示数量。

书架卡片的“作品操作”菜单可以直接打开“作品信息”“故事分支”和“导出、备份与同步”，也可以归档作品；已归档的作品可以恢复到书架或删除。

打开一部作品进入它的工作区，所有内容都在这里，不再逐层跳转。手机底部有四个分区：

| 分区 | 内容 |
| --- | --- |
| 正文 | 章节、写作目标。宽屏时右侧直接是阅读器本体：翻页、进度、书签、搜索、排版主题和 HTML 界面都在，点目录里的章节阅读器跟着跳，阅读器翻到哪一章目录也跟着亮；阅读器顶栏的“编辑本章”进入编辑器 |
| 资料 | 人物、设定、时间线、关系图和地图 |
| 助手 | 此作品的编辑对话和任务 |
| 插图 | 图库、导入、生成插画 |

宽屏（桌面、平板横屏）分三栏：**目录 | 正文 | 工具**。最右侧的窄工具栏用图标切换助手、资料和插图，悬停可查看名称，在旁边的右栏打开；中间始终是当前章节的阅读器，切换右栏不会改变它；左侧是正文目录，点章节中间跟着跳，阅读器翻到哪一章目录也跟着亮。顶栏左右两端各有一个面板按钮，分别收起或显示左栏目录和右栏工具，两侧互不影响；再点一次已打开的工具同样会收起右栏，两侧分隔线都可拖动调宽，宽度和收起状态会保留。

书名下方显示当前分支，点它进入分支管理：切换、分叉、比较、探索走向。右上角“阅读”打开独立阅读器；菜单里是作品信息、角色卡与写作预设、故事分支，以及“导出、备份与同步”。手机上在资料、助手等分区按系统返回，先回到正文，再按一次才离开作品；宽屏按返回直接离开作品。

写作时不必离开编辑器：编辑器顶部的助手按钮在宽屏上把助手停靠在正文右侧，再点一次收起；手机上助手以大的悬浮窗从底部升起，正文仍露在上方，下滑或点“收起助手”即回到正文。从编辑器打开的助手参考范围自动截至当前章节；助手写入后，正文会直接更新。

## 第一本小说

书架的“新建作品”（桌面 `Ctrl/Cmd+N`）有三种开局，书架为空时也直接列出：

| 开局 | 做什么 |
| --- | --- |
| 空白作品 | 填写书名、简介、题材、文风、叙事视角和目标，从第一章写起 |
| 从角色卡开始 | 选一张已导入的角色卡，或直接选 PNG、JSON、CHARX 卡片文件；再选开场作为第一章（见下一节） |
| 续写已有小说 | 选 TXT、Markdown 或 EPUB，预览识别出的章节后导入，接着往下写 |

桌面上也可以把小说或角色卡文件直接拖进书架，按文件类型走对应的开局。同一张卡再次导入会沿用资源库里已有的那份，不会重复。

导入小说时会按“第一章”“第十二回”“序章”“番外”这类标题分章，卷标题并入紧随其后的第一个章名；Markdown 按标题分章，EPUB 按书脊顺序。没有章节标题的文本作为一个“正文”章节导入，长章节保持完整。TXT 支持 UTF-8、UTF-16 和 GBK。书名、简介取自文件，导入前可以修改。导入的正文进入版本历史，原文件不会被改动。

也可打开内置“雾港来信”示例；示例只包含本地样本，不消耗模型额度。

正文自动保存；“保存并返回”或桌面 `Ctrl/Cmd+S` 立即保存。历史版本恢复形成新版本；这一章的故事变量（含 MVU 状态）也回到那个版本时的样子，后面章节的变量不变。不要把强制结束系统进程当成保存操作。

正文只按章节组织，章内不再有二级拆分。旧作品升级时，同一章内原有的多个场景会按原顺序合并为一章正文，章节的顺序与名称保留。

## 从角色卡和预设起步

资源 → 导入资源。选择类型后，查看导入预览和诊断。角色卡可使用 JSON、PNG 或 CHARX，其他资源使用 JSON。

新建作品 → 从角色卡开始，或在角色卡详情选“从角色卡新建小说”。选择一个开场和人设（默认“我”，见下文“人设”）。未选择的备用开场不会成为已发生剧情。卡中明确的人物和世界资料带来源；示例对话仅供文风参考。

在作品菜单的“角色卡与写作预设”中选择预设（生成正文前的预览页也有入口）。采样参数和提示词的修改自动保存到当前分支，预设名旁显示“已自定义”，预设库原件和其他分支不变。切换预设再切回来会保留本分支的调整；“恢复预设”清除当前预设的分支调整。“存入预设库…”可将当前配置存成供其他作品选择的新预设。重命名、归档和完整 JSON 编辑在资源库进行；资源库编辑仍创建新版本。已归档的资源可以在详情页删除，仍被作品的写作配置或资料使用的不能删除。现代聊天预设和提示词包提供条目开关、上下移动、内容/角色/注入深度/优先级与禁止覆盖编辑，未知字段保留。

生成前可查看实际提示词、资源版本、参数及兼容诊断。模板 helper、世界书扩展或模型预填不能靠“成功导入”绕过；调整配置或选择能处理该参数的连接。未支持的宏和缺少结束 `}}` 的宏都和在 SillyTavern 中一样保留原文，只在诊断中提示，不阻止生成。正文生成不会自动带入全部编辑对话。

世界书和 SillyTavern 一样共用一份预算，在设置 → 世界书预算里调整：“占提示词上限的比例（%）”（1–100，默认 25）和“预算上限（token，0 为不限）”（0–65536，默认 0），即 ST 世界信息设置中的 Context % 与 Budget Cap，对所有世界书一起生效，不按作品分开。提示词上限是连接的上下文长度减去预设的回复长度，所以预设的回复长度很大时预算也会变小。预算不够时，预览页只显示一条提示：几个条目没有放入、本次预算多少 token、是比例还是预算上限造成的；点“调整世界书预算”可直接修改，关闭后自动重新预览；“未放入的条目”列出具体是哪些。阅读器里一键写作（“写下一章”、预设填入的写作要求、“重新生成”）不经过预览页，这条提示会在开始写作时弹出，同样带“调整世界书预算”，这一章照常写，新的预算从下一次写作起生效。助手写正文时，其工具结果里也带这条提示。这只是提示，不阻止生成。每个写作任务都记下当时使用的这两项设置。

## 人设

`{{user}}` 和 `{{persona}}` 来自作品绑定的人设。内置人设“我”的名字就是“我”，故事会用“我”称呼你。在资源库顶部的“人设”里新建或修改人设，在“从角色卡新建小说”页或作品的“角色卡与世界书”页选择绑定哪一个。修改人设对之后的生成和显示立即生效，已经写下的正文不变；正被作品使用的人设不能删除。

人设有名字、人设描述、外貌、默认服饰和最多 8 张参考图。模型看到的 `{{persona}}` 是人设描述后接“外貌：”“服饰：”两行，编辑页底部可以预览。三个按钮帮你少打字，结果只填进表单，保存前都能改，“撤销”回到填入前的文字：

- **看图反推**：资料整理模型看前 4 张参考图，写出外貌和服饰；人设描述为空时顺便写一版。需要能看图的 OpenAI 兼容连接，本地 Claude Code / Codex 连接不支持。
- **AI 补全润色**：哪怕只写了一句，也会补全并润色各项；已经填写的名字保留。
- **生成参考图**：资料整理模型把外貌和服饰写成提示词，你确认或修改后，用插画模型画一张加进参考图。

人设只保存在本机，参考图不随作品导出或同步。绑定“我”的作品在每台设备上都用该设备自己的“我”，修改“我”不会让作品重新同步。绑定其他人设的作品会带上人设的文字：在另一台设备导入时，复用内容完全相同的人设，没有就新建；修改这类人设后，用到它的作品下次同步时会重新上传。旧版本填写的主角名字已自动换成人设：默认的“主角”改为“我”，自定义的名字和身份变成同名人设。

## 配置模型和生成正文

设置 → 添加模型连接。OpenAI 兼容端点通常填写以 `/v1` 结束的基础地址。模型名称可以每行一个或用逗号分隔，也可以获取服务端列表后多选；同一连接内的模型共用地址和密钥。按连接实际能力选择“文本模型”“生图模型”或“文本与生图”。旧连接保留原有用途，需要时可编辑分类。

OpenAI 兼容文本连接的“高级参数”中，`top_k`、`top_a`、`min_p`、`repetition_penalty` 默认开启，各自有开关。开启时发送预设中的值，预设未设置就不发送；后端不接受某项时可关闭，保存后会记住选择。其他后端参数仍可在“后端支持的额外参数”中用逗号分隔填写。

在“任务使用的模型”中为正文、编辑 Agent、资料整理和插画分别选择具体模型。写作和插画生成页也可以为本次任务切换模型；切换写作模型后需要重新预览提示词。每次任务只调用一个模型。密钥以明文保存在本机的密钥文件 `secrets.json` 中，不进入作品备份、同步和导出。

### 使用 NovelAI 生图

1. 设置 → 添加连接，选择“NovelAI（生图）”。默认地址为 `https://image.novelai.net`，无需添加 `/v1` 或 `/ai/generate-image`。
2. 在 API Key 中填写 NovelAI 账户设置中的 **Persistent API Token**。默认模型为 `nai-diffusion-4-5-full`；“选择常用模型”的内置列表也包含 V5 Full（`nai-diffusion-5-full`）和 V5 Curated（`nai-diffusion-5-curated`）。列表不联网、不验证密钥，也可手动填写模型 ID。
3. 在插图生成页面选中该连接，填写画面描述并选择尺寸。默认生成一张 1024×1024 图片，28 步，引导强度 5，随机种子。
4. 高级参数示例：`{"negative_prompt":"blurry, low quality","steps":28,"scale":5,"seed":123}`。还支持 `width`、`height`（64 的倍数）、`sampler`、`noise_schedule`、`cfg_rescale`、`sm`、`sm_dyn`、`dynamic_thresholding`；具体可用值受模型限制。显式选择的尺寸优先于 JSON 中的宽高；`seed: -1` 表示随机。

当前支持直连文生图，不支持参考图编辑、Vibe Transfer、角色定位、局部重绘或放大；应用会拒绝参考图及未支持的参数。提示词原样发送，不自动添加质量标签。取消或超时只停止本地等待，服务端可能继续生成并计费；不会自动重试，手动重试会新建请求。SillyDraft 远程执行器暂不支持 NovelAI 配置。

### 使用 ComfyUI 生图

1. 在 ComfyUI 中保存工作流。
2. 在 SillyDraft 添加连接，选择“ComfyUI（生图）”，填写服务根地址，例如 `http://127.0.0.1:8188`。手机访问电脑时应填写电脑的局域网地址，并确保 ComfyUI 允许局域网连接。如果反向代理要求 Bearer 密钥，在 API Key 中填写；本地无鉴权服务留空。
3. 点“获取服务端工作流”，选择文件名，再选择接收画面描述的输入（通常是正向提示词节点的 `text`，不要选负向提示词）和图片输出节点（通常是 `SaveImage`）。画面描述默认只列出 `text`、`prompt`、`text_g`、`text_l`；自定义字段可展开“高级设置”后选择全部字符串输入，已保存的绑定会保留。需要参考图时，选择 `LoadImage` 节点的 `image` 输入。
4. 保存连接。模型、尺寸、采样器等默认沿用工作流，不必另填模型名称。

新建生图任务时会按文件名重新读取最新保存内容，并将节点图和绑定冻结到任务中；重试已有任务仍使用原来的快照。读取失败或绑定的节点被删除时会报错，不会偷偷使用旧文件生成。服务端需开放 `userdata` 接口；读取画布还需要 `object_info` 节点定义接口。

标准 ComfyUI 核心节点的画布文件可直接读取，支持命名控件、常规控件顺序、种子控制和节点连线。自定义前端节点、子图、禁用或绕过模式等不能可靠转换时，会指出问题并提示使用 **Export (API)**。自定义节点工作流可在“高级设置”中导入 API 文件或粘贴 JSON 后点“解析 JSON”。本地导入使用固定快照。

“高级设置”也可绑定模型加载器输入（例如 `ckpt_name` 或 `unet_name`），启用手动填写或获取多个模型；仅需要覆盖工作流模型时使用。“检查连接并获取模型”只检查该加载器的模型列表，不代表工作流已完成实际生图验证。

尺寸、采样器、步数等沿用工作流。每次生成自动替换数值型 `seed` / `noise_seed`，也可在高级参数填写 `{"seed": 123}` 固定种子。首版要求所选输出节点只返回一张图（`batch_size=1`）。参考图按顺序填入绑定的参考图输入，张数不能超过输入数；添加了图生图工作流时，带参考图的插图改用它（见下文“图生图工作流”）。自定义节点和模型需提前装在 ComfyUI 服务端；工作流不能包含密钥。

取消会停止本地等待，ComfyUI 服务端可能继续运行；应用不会调用全局中断去打断其他任务。等待超过 10 分钟会报告超时，重新生成前可先查看服务端任务状态。本次支持自部署 ComfyUI 直连，使用其[官方工作流、历史和图片接口](https://docs.comfy.org/development/comfyui-server/comms_routes)。

编辑 Agent 适合理清人物动机、检索资料、委派写作或提出资料更新。它的回复不算正文。进入生成任务查看原始输出、错误或结果，再进入助手页“⋮”菜单里的“候选”比较；采纳才更新作品。

助手页只显示对话，“候选”“任务”和“删除当前会话”收在会话一行右侧的“⋮”菜单里。会话一行还有参考范围、预设和技能三个图标，悬停可看当前设置，点击进入调整。对话顶部的“生成正文”和候选列表的“生成正文候选”为参考位置的章节生成候选。“参考范围”决定助手能读到哪里：默认是分支末尾，也可以选到某个章节，之后的正文与资料不会被看到。第一次发送消息时才会创建会话，只是打开助手页不会留下空会话。没有配置可直连的模型时，页面会提示并可一键前往设置。

首轮回复完成后，会用当前文本模型再发起一次简短请求，自动概括会话标题，替换默认的“创作会话”。后续聊天不会重复命名；命名失败时保留默认标题，已完成的回复不受影响。

每条消息都能“复制”。你发出的消息可以“修改”：原话回到输入框，改完发送后，这条消息和它之后的对话都会被替换，助手从这里重新回答。对话最后一条回复可以“重新生成”：旧回复连同这一轮的工具记录一起丢掉，用你上一句话再问一次；这一轮失败或被停止时，提示卡片上的“重试”效果相同。被替换的那一轮里助手已经写入的正文、提出的资料建议和生成的插图都会保留，正文旧版本可在版本历史里恢复。桌面上这些按钮在消息下方，手机上长按消息弹出。

输入框左侧的闪电按钮里有**续写**、**修改**、**总结**、**查找**、**归纳**等快捷操作。点一下会把对应的请求填进输入框（不会直接发送），可补充后再发：续写和修改让助手为当前章节生成候选，总结概括这一章，查找在可见正文里搜索人物、物品或台词出处并给出所在章节和上下文，归纳把人物、地点、设定和伏笔整理成待审阅的资料建议。宽屏时“当前章节”是中间正在看的那一章，助手也知道你在看哪一章；助手只能改写它能看到的最后一章，所以对更早的一章续写或修改时，参考范围会自动移到那一章。

配置生图渠道后，快捷操作会出现 **本章亮点生图**。点击后直接让助手从当前章节提取默认 3 个不同的视觉亮点（内容不足时减少），每个亮点写成一段生图提示词。整组提示词、负面提示词及参考图在同一个确认卡片中展示，点一次“确认生成”后按顺序逐张生成。取消或某张失败会停止剩余图片，已完成的图片保留在对话和作品素材中；不会自动重试。生成期间停止任务时，已完成的图片仍可在作品素材中找到。该操作不修改正文；查看较早章节时，参考范围会移到该章。

“推演结局”会填入讨论三个结局的请求，根据截至当前章节的故事考虑人物选择、伏笔回收和最终结果。补充要求后发送即可讨论，不会直接创建分支或修改正文、资料。

生成或改写的正文写完直接写入，旧版本可在编辑器的版本历史里恢复。选中正文片段后可局部改写，结果只替换选区。生成期间继续编辑导致依据版本过期时，结果不会写入，留在助手菜单的“未写入”里；保留当前稿，在新版本上重新生成或手动整理两份内容。

**图生图工作流**：在连接设置里点“添加图生图工作流（参考图生图）”，选择一个带图片输入的工作流（如 Qwen-Image-Edit、Kontext 类），绑定画面描述和一到多个参考图输入。插图带参考图时改用这个工作流，参考图按顺序填入各个输入；参考图少于输入时，余下的输入重复填最后一张。参考图多于输入数时会报错，并指出输入数上限。图生图工作流沿用其中保存的模型，不绑定模型输入；连接的多个模型只用于文生图工作流。

### 用量与成本

页面顶部的柱状图按本地日期展示近 30 天的每日用量，可切换成本、Token（输入与输出合计）和调用次数，点击某一天查看具体数值。没有请求的日期留空；没有价格的请求仍计入 Token 和调用次数，成本详情会标明“无价格”。

每次模型请求（写作、助手、旁路整理、生图、连接测试）结束后都会记一笔。设置 → 用量与成本显示累计和本月的金额，点开后按月、按连接与模型列出请求次数、输入 / 输出 token 和金额。金额为美元：上游返回了成本（如 OpenRouter、Claude Code）就用上游的；没有时，OpenRouter、ElectronHub、Chutes 按 SillyTavern 的做法用模型列表单价乘 token 数；其余请求只记 token，算作“无价格”，不计入金额，设置里会写明有几次。上游没返回 token 数，或请求中途失败、取消时，token 按字数估算，标为“≈”。Claude Code 用订阅登录时，它报告的是按 API 价折算的金额，不是实际扣费。记录属于整个作品库，删除作品不会删除记录，也不进入作品备份。用手机连接桌面时，看到的是桌面上的同一份记录。

## 资料、地图与故事分支

作品工作区的“资料”分区支持手工创建人物、设定、组织、物品、地点、事件、暗线和伏笔。区分事实、计划与推测，附上来源。AI 提取结果先进入审阅页；未采纳建议不会成为故事事实。修改来源正文后，相关资料会提示来源过期。

关系页创建有方向的关系，选择两端人物和类型；手机可选择关注人物查看附近关系。地图页选择或生成底图，再添加地点标记与路线。标记坐标按图片尺寸归一化，地图编辑保存后才能在别处使用。

分支管理（点书名下方的分支）可以从选定章节分叉、重命名、切换和比较分支，也可回看已有的走向候选。想沿章末的某个走向探索新路线，可以直接在走向卡片上点“另开分支写”；想讨论结局，可用助手里的“推演结局”快捷操作。较早位置的分支不携带后来发生的设定、关系变化或宏变量。

### 旁路整理

开启旁路整理后，每写完一章（续写、改写，或采纳助手提出的正文候选），SillyDraft 会在后台运行一次旁路整理，直接更新资料：

- **管理人物**：新出场的人物自动建条目；已有人物更新外貌、服饰、动机、当前状态与经历；人物关系随剧情更新。主角 {{user}} 也有一个人物条目。
- **整理线索 / 记忆**：每章记一条事件，作为长篇的记忆；记录埋下与回收的伏笔，以及地点、物品、组织。
- **推演剧情**：预测后续走向（标为“创作计划”），推演镜头外的人物与势力在做什么（标为“尚待证实”）；已应验的改为“已确认”，被推翻的删除。

这些资料按章节留版本：按“资料截至哪个故事位置”可回看任一章时的状态，从中间分叉会带上截至那一章的资料。章节被改写后会针对新正文重新整理。

旁路整理的结果会进入之后的写作上下文。续写下一章时，若上一章的旁路整理还在进行或还没启动，会先等它完成（最多 3 分钟），并提示“等待上一章的旁路整理完成后再写…”。在设置 → 旁路整理里，“写完一章后自动整理”只在“任务使用的模型”里选定了能调用工具的资料整理模型时默认开启，否则默认关闭；你打开或关闭过它，就一直按你的选择。三项职责（管理人物、整理线索 / 记忆、推演剧情）可各自单独关闭，默认全开；资料页的“重新整理本章”可手动重跑，不受开关限制。每次整理会额外调用若干轮模型（最多 8 轮），每轮都会重发本章正文和资料索引。旁路整理要调用工具，需要 OpenAI 兼容接口或本地命令行工具的连接，远程执行器暂不支持：没有这样的资料整理模型时不会自动改用写作模型，只有你手动打开开关或手动重跑才用写作模型。开关下方写明它为何默认开或关，以及整理用哪个模型。

## 插画和阅读

“插图”分区的生成入口填写描述，选择生图连接及参考资源；任务完成后保存到图库。可以设为封面、地图底图或在正文光标处插入。图片保留提示词、模型、来源版本与参考图信息。任务失败不会修改正文；重试会创建新任务，可能再次收费。

在阅读器里选中一段正文，菜单中的“生图”会把选段连同本章交给编辑助手：助手会知道生图引擎的类型、模型和你保存的默认设置，按该引擎的写法自行编写提示词（可查阅资料和全书）。提交生图前，对话里会出现确认卡片，显示图片名称、生图引擎（连接名称；ComfyUI 显示工作流文件，绑定了模型输入时再显示模型）、提示词和负面提示词；点“确认生成”才会调用当前的生图模型。点“取消”或停止回复则不生图，对话里留下“已取消生图”记录，助手也不会自动重试。图片显示在对话里，同时进入图库。图片左下角的“插入正文”图标会把图片放到引用段落下方，“下载到本地”图标可保存图片（手机使用系统分享菜单）。如果引用正文已改变，或旧记录无法唯一定位引用段落，会提示重新选取，不会自动改用章节末尾。参数沿用“生成插画”页上次为该模型保存的尺寸、质量和额外参数；助手还可以把出场人物的形象图作为参考图一并交给生图引擎（见“人物形象图”）。NovelAI 或默认参数里已有负面提示词时，助手可以给出自己的负面提示词，替换保存的那一条。尚未配置编辑助手或生图模型时，“生图”显示为灰色，助手也不会获得生图工具。

章节编号按目录顺序自动生成，名字单独填写，可以留空。新增章节时只填名字；重命名只改名字，编号不变；调整顺序或删除章节后编号自动重排。序章、楔子、番外等可在章节菜单里选“不计入编号”，它们只显示名字，也不占号；选“计入编号”时，名字开头残留的“第N章”会自动去掉。作品信息里可以把编号设成中文数字（第六章）或阿拉伯数字（第6章）。导入的书保持原来的标题显示：编号与顺序对得上的章节自动计入编号，其余（如带卷名、跳号的章节）原样保留；跳号的书可以在跳号那一章的菜单里选“从此章起全部计入编号”，这一章和其后名字仍以“第N章”开头的章节一并计入编号、连续排号，番外等其他章节不受影响。续写下一章时，新章节自动编号，名字取所选走向；生成后只有编号的章节会按正文自动起名。

手机端点击正文目录中的章节，先进入阅读器预览，点顶栏的笔形“编辑本章”按钮再编辑；保存返回预览，再返回正文列表。桌面宽屏下列表与阅读器同屏显示，点笔进入编辑器，保存后回到同屏预览。右上角“阅读”打开的独立阅读器也提供编辑按钮。

阅读器直接读取已保存正文与插画。从目录打开时显示所选章节，从“阅读”入口打开时停在上次读到的位置。“排版与主题”中的“隐藏 HTML”和“隐藏插图”可以独立开关，分别记住选择。本章有被隐藏的插图时，顶栏会显示“插图已隐藏”，点“显示插图”只恢复图片，不改变 HTML 的设置。已经插入正文的图片无需重复插入。

开始阅读后上下栏自动收起，只留页眉的章名和页脚的全书进度、时间。点屏幕任意位置显示或收起菜单。桌面可用 `←`/`→`、`PageUp`/`PageDown`、空格翻页，翻过一章的结尾直接进入下一章，在一章开头上翻回到上一章结尾。底栏的进度条可拖动跳到任意一章，并估算本章还需几分钟；目录对上千章的长篇也能直接定位到当前章，每个章节只显示一行。

“排版与主题”可调字号（`A−`/`A+` 或滑块）、字体（默认、宋体、黑体、楷体，按系统已安装的字体显示）、背景（纸白、羊皮纸、护眼、灰调、夜间、纯黑）、亮度（在系统亮度之上再调暗）、行距、段距、字间距、页边距，以及首行缩进、两端对齐、对白高亮、斜体淡化、读到结尾自动构思走向和阅读时屏幕常亮；调整时页面即时变化，“恢复默认”一键还原。开启“系统深色时自动夜间”后，应用为深色时自动使用夜间背景；底栏的“夜间/日间”可直接切换。设置了段距时，正文里原有的空行会被折叠，导入的小说也能排得整齐。缩进统一由“首行缩进”决定：正文段首原有的空格（包括模型输出里的全角空格）不显示，开启时每段统一空两格，关闭时都不缩进；代码不受影响，正文和导出内容保持原样。正文按 SillyTavern 显示聊天消息的方式呈现：`*斜体*`、`**加粗**`、`***粗斜体***`、`__下划线__` 显示为对应格式并隐去标记符号；“对白高亮”把 `"…"`、`“…”`、`「…」`、`『…』`、`«…»`、`＂…＂` 内的对白（同一行内闭合）显示为琥珀色，“斜体淡化”让引号外的斜体变淡，两者默认开启，颜色随背景调整。代码片段和 HTML 界面不受影响；这只改变显示，正文本身和导出内容中的符号保持原样。

“自动滚动”按设定速度匀速下移，到一章结尾自动接上下一章；悬浮条可加速、减速或停止，点一下页面也会停止。书签显示所在位置的一段原文和添加日期，阅读器同时提供搜索。删除 Agent 会话不会删掉小说。阅读器不显示模型原始推理、工具日志或未写入的正文。 标题、列表和引用保留编辑格式。若生成使用了 ST 显示正则，阅读器按当时的规则呈现；在“阅读设置”中可切换“显示原正文”。未写入正文的对比页也可关闭“预览显示效果”。这些显示变化不改写采纳及导出的正文。

读到最后一章的结尾，会出现“接下来会怎样？”：配置了整理模型时，结尾一进入视野，整理模型就自动根据全书内容提出三个不同的后续走向，每个有标题和概要；没有配置模型、在“阅读设置”里关掉了“读到结尾自动构思走向”，或者上次生成失败、被取消时，点“生成三种走向”手动生成。每个正文版本只自动生成一次，已有走向仍适用时不会重复调用模型。

选一个走向点“写下一章”，就在全书末尾新建一章（按原有章节编号续排，如“第二章 出海”），阅读器直接翻到这一章，写作模型按当前分支的预设、角色卡和世界书写出的正文边生成边显示在页面上，不会跳到其他页面。写完自动收下，不需要再审阅；“调整要求”在卡片里展开写作要求，可修改后再写。每一章的故事变量（包括 MVU 状态）在写入时都随这一章保存一份快照，之后可以在任意一章分叉，新分支从那一章的状态继续；在故事分支里切换回旧分支即可回到之前的走向。生成中可以“停止”；失败或停止后这一章留在末尾，点“重新生成”继续写，或再选一个走向写进这一章。若生成期间你改动了这一章或故事变量，结果不会覆盖你的改动，页面会提示，可选择“写入这一章”或“重新生成”。新的一章写完，读到它的结尾时又会自动提出新的三种走向；“换一批”重新提出走向。每张卡片上的“另开分支写”会以该走向的标题创建独立分支，保留当前分支的正文、资料和变量，再按卡片的要求写下一章并切到新分支；调整过的要求同样适用。原分支保持不变，可以从书名下方的分支入口切回。

已写入的章节末尾也有“重新生成”，模型返回拒答文字或对结果不满意时都可以使用。它沿用本章最近一次写作要求和当前写作配置，生成完整正文后替换当前章，不会新增章节或追加到原文后。生成中和失败时保留原文，旧版本仍可在历史中恢复；若期间正文或变量有改动，结果不写入，留在章节末尾等待处理。

### 人物形象图

选文生图与本章亮点生图会自动带上当前章节范围内的人物外貌、默认服装、状态，以及触发的世界书资料。助手按单一画面组织动作、人物位置、视角和光线，只描述可见部位；正文明确写出的换装或状态变化优先于默认资料。NovelAI 使用标签提示词，ComfyUI 会结合工作流模型信息选择标签或自然语言，模型不明时使用自然语言。这些规则帮助减少人物漂移，但仍需在确认卡片中检查模型实际写出的提示词。

在资料页打开一个人物条目，除“服饰”“当前状态”外，可以管理最多 8 张形象图：“选择或导入”“生成形象图”（先由模型按外貌和服饰拟好提示词，确认后出图），主角条目还能“从人设导入”。形象图跟着人物的版本走。

让助手画插图时，它会自己查资料里的出场人物，把外貌写进提示词，并把形象图作为参考图一并交给生图引擎；确认卡片会显示带了哪几张参考图。手动生图页也可以“选择人物形象图”。

## HTML 开场与状态栏（酒馆助手兼容）

不少角色卡用 `html` 代码块做开场界面、状态栏或行动选项，在 SillyTavern 里依赖酒馆助手（JS-Slash-Runner）渲染。SillyDraft 内置了同样的渲染方式，不需要安装扩展：阅读器把正文里的 `html` 代码块（以及内容含 `<html>`、`<head>`、`<body` 的任何代码块）放进一个隔离的网页视图，高度随页面内容自动变化；正则替换出来的 `<div>`、`<details>` 等块级片段去掉脚本后同样按 HTML 显示。从角色卡开始时，开场预览就会显示这个界面，开场源码折叠在下方仍可编辑；若卡片附带酒馆助手脚本，页面会列出脚本名称并说明脚本库不会运行。

预设的剧情选项如果原本通过填写酒馆输入框来推进，现在填写的内容会直接作为下一章的写作要求，无需再确认：阅读器翻到新章，边写边显示，完成后自动保存，继续沿用当前分支的模型、预设、角色卡和世界书。这样新建的章节只有编号（如“第四章”），写完后会用整理模型（没有配置时用写作模型）读这一章，拟一个章名接在编号后面，如“第四章 桌底下的契约”，起好名再开始旁路整理，这一章的事件按新章名记录；生成期间你已改过的章名不会被覆盖，拟名失败时保留编号。直接赋值、输入事件、发送按钮以及 `/setinput` 都适用；重复事件只启动一次，已有写作任务时会提示等待。角色卡尚未创建小说时，预览只记下要求。

界面里的脚本能用酒馆助手的常用接口，SillyDraft 把它们对应到小说：每一章是一条消息，第一章的“消息页”（swipes）是角色卡的各个开场，所以“切换到第二个开场”之类的按钮可以直接替换第一章；`getVariables`/`replaceVariables` 等读写当前分支在该章的变量；`eventOn`/`eventEmit` 在同一页面的各界面间传递；`toastr` 显示为提示条；`alert`/`confirm`/`prompt` 弹出对话框。`triggerSlash` 支持 `/send`、`/sys`、`/sendas`、`/trigger`、`/cut`、`/echo`、`/pass`、`/setvar`、`/getvar`、`/setglobalvar`、`/getglobalvar`、`/addvar`、`/incvar`、`/decvar`、`/flushvar` 和管道 `|`。发送类命令不会自动生成：`/send 文本` 或 `/trigger` 会打开写作请求并把文本填入写作要求，由你确认后才生成；`/cut 楼层 | /trigger` 变成对该章的整章改写，界面在新正文写入后被取代。界面不能删除章节，也不能直接调用模型（全局 `generate` 会报错，`SillyTavern.getContext().generate()` 只提交已填入的续写要求）。

安全边界：页面从固定的保留地址加载，只能通过 HTTPS 请求网络（字体、CDN 库、图片），不能跳转到其他网址、读取本地文件、使用摄像头或麦克风，也看不到模型密钥和其他作品。页面能看到的只有当前分支的正文、变量和角色卡元数据。设置中的“渲染正文中的 HTML 界面”可以整体关闭，关闭后按源码显示；阅读器菜单的“显示原正文”同样会显示源码。Windows 和 Linux 暂无内嵌网页视图，显示源码。

## MVU 变量（MagVarUpdate 兼容）

很多角色卡用 MVU 维护人物数值、物品和世界状态：世界书里名字含 `[InitVar]` 的条目给出初始变量，模型在每次回复末尾输出 `<UpdateVariable>` 块（`_.set('主角.生命', 100, 80);//受伤` 这类命令，或 `<JSONPatch>` 里的补丁），状态栏再把变量画出来。SillyDraft 内置了这套规则，不需要安装脚本：

- 从角色卡开始时，角色卡世界书的 `[InitVar]` 条目（即使是关闭的）会生成第一章的变量；开场里的 `<initvar>` 块和 `_.set` 命令也会生效。之后绑定的额外世界书可以在变量管理器里“重新读取初始变量”。
- 生成正文时，提示词里的 `{{get_message_variable::stat_data}}` / `{{format_message_variable::stat_data}}` 会填入当前章的变量；模型回复里的命令按 MVU 的规则执行（路径必须存在、`[值, 说明]` 只改值、不可扩展的对象和数组拒绝插入等），结果随生成结果一起保存，正文写入时写入该章。正文末尾会附上 `<StatusPlaceHolderImpl/>`，角色卡的显示正则据此渲染状态栏；它不会进入提示词。
- 每一章的变量等于“上一章的变量 + 本章正文中的命令”。手动改过正文后，可以在变量管理器里按本章重新推算，或从头“重新处理变量”。
- 角色卡自带 MVU Zod（`registerMvuSchema`）脚本时，结构校验默认关闭，模型可以自由新增键；可在变量管理器切换。脚本本身的取值范围修正不会运行。

变量管理器在“资料”页右上角的“故事变量”图标：全局、聊天、消息楼层、角色、预设五个分页各有一个 JSON 编辑器，聊天页显示 MVU 状态和最近一次变更。

## 备份、导出和同步

工作区右上角菜单的“导出、备份与同步”导出 TXT、Markdown ZIP、EPUB，只包含选定分支的已采纳正文与所需图片。TXT 用文字标记图片；Markdown ZIP 解压后相对路径图片可一起迁移。

加密 `.sillydraft` 作品备份包含版本、分支、任务、资料、图片和原始 ST 资源，密码至少 12 个字符。密码不随备份保存，丢失后无法恢复。模型连接密钥不随作品备份迁移；新设备需要重新设置连接。

从书架恢复备份，先预览，再选择作为独立作品导入或在版本检查通过后替换。损坏文件、错误密码或不合法引用不会部分改写当前作品。

可选同步使用你控制的 HTTPS 文件端点，需要强 ETag、GET 与 `If-Match`/`If-None-Match` 条件 PUT。两台设备使用相同地址和备份密码。同步为手动整部作品快照传输；并发修改会保留冲突副本，再明确选择本地或远端版本。选择一侧仍会为另一侧保留副本；没有实时多人协同编辑。

## 版本与更新

设置页底部显示当前版本。Android、macOS、Windows 和 Linux 版启动时每天最多访问一次 GitHub，检查是否有新的正式版本；有新版时显示更新说明，可以“下载”（用浏览器打开本平台的安装包）、“跳过此版本”或“稍后”。下载后需要手动安装，作品库随安装保留。设置里可以随时“检查更新”，也可以关闭“自动检查更新”，关闭后应用不会自行联网检查。iOS 版没有发布安装包，不检查更新。

不要用旧版本打开新版本用过的作品库：旧版会提示升级，并且不会改动数据。当前版本也不再升级更早版本的作品库和备份：打开旧作品库会提示无法打开，导入旧备份会提示格式不支持，数据都不会被改动。

## 手机使用桌面上的作品库

**桌面上**：设置 → 手机连接 → 打开“允许手机连接”。页面显示二维码和连接链接；桌面有多个网络地址（如 Tailscale）时可切换。开关状态会保留，下次启动自动恢复；端口被占用时显示原因并保持关闭。“重新生成密钥”后，已配对的手机需要重新扫码。

**手机上**：书架左上角点“SillyDraft ▾” → 扫码添加桌面（或粘贴链接）。连接成功后书架、正文、资料、任务都是桌面上的那一份，生成在桌面上执行，手机锁屏或退到后台不影响。每次打开应用都回到本机作品库；从同一个菜单切换。桌面和手机的作品库互不影响。

- 两边须为同一版本，不一致时会提示双方版本。
- 连接断开时顶部显示提示条并自动重连，编辑中的文字保留；断开期间的保存会报错，重连后再保存。
- 断开时点“切回本机”：若有未保存的修改或阅读位置写不回桌面，会先询问“放弃并切换”。
- 远程模式下不能新增或编辑模型连接（密钥只在桌面里），可以为各任务选择连接。桌面把每个连接的地址与本机保存的密钥绑定：连接地址被改动（包括从手机改动）后，桌面拒绝使用该密钥，需在桌面重新保存连接。
- 桌面上的本地订阅（Claude Code / Codex）连接暂时只能在桌面上使用，手机选用会提示“本地订阅只能在桌面上使用”；手机上请选 API 连接。
- 持有连接链接即可读写桌面上的全部作品并用桌面的模型付费调用。只在自己的设备间扫码。

## 扫码传输

资源库的角色卡、预设、世界书、正则，以及助手技能、人设、模型连接都可以“扫码分享”：另一台设备在书架菜单里扫码（桌面上粘贴链接）即可收到一份副本。

- 分享页开着时有效，最长 10 分钟，被接收一次即失效。
- 两台设备需在同一网络。手机作为分享方时请停留在分享页。
- 模型连接的分享页把“含 API Key”警告放在二维码上方：看到二维码的人就能使用这把密钥。
- 接收的本地订阅（Claude Code / Codex）连接不带命令路径，接收方自动查找本机命令。
- 角色卡连同修改过的版本与卡内图片一起传输。

## 任务中断与远程执行

助手回复期间可以继续发送消息，同一会话按发送顺序处理，输入框上方显示队列并可逐条取消。每条消息开始时读取最新会话和正文，接上前一轮的结果；停止当前回复或某条失败后，后续消息继续处理。应用退出后，尚未完成的本地消息会标为中断，可在任务记录里手动重新生成；不会自动恢复请求。

直连任务在应用退出、网络断开后保留已有输出，不能恢复已经断掉的模型流。“重新生成（新任务）”会再次调用模型。

个人远程执行器可在手机断开后继续工作；重新打开任务页点击“获取远程结果”查询原 ID，不会补发一笔新请求。取消需得到服务端确认。部署与详细限制见 [远程执行器](../server/README.md)。手机使用桌面上的作品库时，任务本来就在桌面上执行，见上一节；独立的个人远程执行器适合手机用本机作品库、借用服务器上模型的情况。
