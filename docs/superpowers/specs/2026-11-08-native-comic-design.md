# 原创漫画直接创作与助手分镜

日期：2026-11-08  
状态：用户已确认，按每次生成一张完整漫画页实施。

本方案取代 `2026-11-07-comic-support-design.md` 中“原创漫画先写故事底稿”的要求，以及新漫画必须以无字单格图片配独立文字阅读的要求。原方案的小说忠实改编、版本保护、任务恢复、资源归属和数据完整性要求继续适用。

## 用户明确的目标

- 新建原创漫画没有“故事底稿”，不要求先写小说，也不在后台生成小说作为必经阶段。
- 作者在漫画开场输入一句剧情要求，AI 随即完成分镜和绘制。
- 后续创作依据现有漫画提供三个剧情方向；选择方向后继续画。
- 小说改编漫画保留小说来源，继续校验改编与原文的一致性。
- 助手具备真正创建漫画分镜的工具，产物进入作品，不能只回复一段分镜描述。

“只有图”指漫画正文与阅读内容。开场指令、分镜结构、对白转录、连续性状态和任务记录仍可保存为创作数据；这些数据不成为小说正文，不提供“编辑底稿”功能。

## 实现方案与取舍

采用现有 `ComicService`、`TaskKind.comic`、漫画不可变版本和图片子任务，扩展为原创与改编两条输入路径，后续共享分镜编辑、绘制、历史、阅读和导出。用户已明确两种产品流程；这项复用方式是实现建议。

单纯隐藏底稿入口仍受 `sourceRevisionId`、原文事实证据和非空正文限制，不能满足目标。另建独立漫画存储和任务系统会重复已有版本、备份和恢复逻辑，因此不采用。

这是涉及核心模型、任务、界面和助手的完整功能调整。实现时按最小可验证单元推进，不重新开发图片供应商协议，不新增依赖。

## 默认选择，供用户核对

1. 每次原创“开始画／继续画”默认产出一张完整漫画页，页内有多个分镜，对白、旁白和音效文字直接在图内。分镜仍单独结构化保存，便于编辑和重画。具体画风、阅读方向沿用作品设置与作者要求，不预设黑白或日式阅读方向。
2. 三个“分支”首先是供作者选择的续画方向，不预先生成三套图片，也不自动创建三个持久故事分支。作者选择一个继续；需要保留不同路线时复用现有“从这里分支”。
3. 输入开场后自动规划并绘制，不增加“确认底稿／确认分镜”的必经步骤。助手中明确只要求“出分镜”时只保存分镜；明确要求画漫画时继续绘制。

用户已确认以上默认选择。

## 作者流程

### 新建原创漫画

创建表单选择漫画后保留标题、类型等通用信息，隐藏小说文风、正文视角和字数目标等写作专用项。创建后进入漫画工作区，显示开场输入，例如“雨夜，一个女孩在末班地铁上收到未来自己的短信”，主操作为“开始画”。不显示底稿编辑、来源与事实、检查改编、改编为漫画等小说专用操作。

复用现有章节作为漫画各话的目录容器；原创章节允许正文始终为空。空章节是否可复用要检查漫画内容与活动任务，不能再根据正文为空判断。没有漫画的初始章节承接第一张漫画页；后续继续画默认在当前话追加一页，不每画一页就强制新建一章。现有新建章节操作用于开始下一话。

开始前解析并校验现有分析模型与生图连接。缺少连接时就地引导配置；配置完成后保留输入。正常路径为：开场指令 → 结构化分镜及连续性检查 → 绘制完整页 → 保存图片与漫画版本。作者看到阶段进度、已完成图片及失败原因，不需要手动串起几个任务。

### 继续画与三个方向

当前最新漫画页完成后，在当前话末尾提供三个方向；自动生成触发与现有小说方向保持一致：首次到达已完成漫画末尾生成，同一漫画版本只触发一次，失败或取消不自动重试。作者也可刷新三个方向或直接输入自己的下一段剧情。

每个方向包含标题、简短剧情和可画的下一步事件，不包含“候选小说正文”。选择一个方向会据此规划并绘制下一页，成功后可生成新的三个方向。一次只提交所选方向的绘图任务，重复点击和并发页面不能重复生成。

方向依据当前分支、截至创作位置的已完成漫画及其分镜、对白、人物状态、场景和参考图。不得读取未来章节、其他分支或把隐藏小说当作真实故事。较长历史可整理连续性摘要，但摘要绑定所依据的漫画版本，不能成为新的正文来源。

规划的确定依据是漫画结构与已画页面对应的记录；绘制会传入已有角色参考图及前页图片，遵守供应商参考图数量与能力限制。当前文本模型协议没有统一的视觉能力声明，本次不新增强制看图协议，也不声称文本方向模型已实际识别图片。后续替换图片会使方向过期；作者可以同时修正对应分镜，不能让模型凭空得知换图中未记录的剧情。供应商不支持参考图时明确提示仅用文字设定。

生成方向和续画均冻结漫画 head、页面顺序和引用版本。期间重画、编辑、恢复历史或移动章节后，旧方向标过期，旧任务不能覆盖新内容。存在未完成页时先提供恢复／处理入口，不把未完成剧情算作已发生，也不自动越过它生成下一页。

### 小说改编

小说章节的“改编为漫画”入口保留，原文、事实引用、原句对白和忠实改编检查继续生效。已有改编文档不能仅因作品类型为漫画就被重新解释为原创。

改编漫画仍由原文驱动；其阅读末尾不自动提供脱离小说的原创续画方向。用户通过助手要求改编时，助手明确使用所选小说章节。将改编作品转换成完全原创的后续故事不在本次范围。

### 阅读、分镜与导出

新生成漫画页在阅读器和漫画 HTML ZIP 中以完整图片呈现，正常阅读不在图片外重复输出对白或小说正文。编辑分镜、替代描述和无障碍文本保留，图片上的文字修改需要重新绘制该页。

分镜是可编辑的制作结构，包含每格画面、构图、人物状态、对白及页内顺序。修改一格会使其所属页图片过期；重画以整页为单位，保留旧图片与历史，不假装修改文字即可更新图片。漫画生成提示应明确包含页内布局、阅读顺序和准确台词，不能沿用“单格、禁止任何文字”的旧规则。

旧版本的无字单格与独立对白仍可完整读取和导出，不删除旧对白、不自动收费重画。用户主动重新绘制后采用新页格式。历史兼容属于旧内容保真，不再给新原创提供底稿流程。

## 核心模型与持久化

扩展版本化 `ComicDocument`，读取 version 1 时按小说改编解释；新写入采用下一文档版本。用明确来源类型区分原创与改编，而不是为原创伪造空的原文 revision 或跳过所有校验。

- 原创保存创作要求、此前漫画依据、分镜、页、对白和连续性状态；不要求原文来源单元、原文事实和原句证据。
- 改编保存原文 revision、全文与前情引用，继续执行完整事实和证据校验。
- 新页记录稳定页 ID、按顺序排列的 panel ID、图片资源／子任务 ID、生成指纹与状态。图片归属于页，分镜描述属于格；资源收集和任务恢复同时兼容旧格上图片。
- 原创的“当前依据”以同分支此前漫画 head、当前目标 head 及章节顺序校验；追加当前话的页面将当前旧 head 冻结在任务中，不在新文档里建立自引用。
- 保存仍检查作品、章节、资源、任务、引用版本的归属和版本冲突。一个来源模式的宽松规则不能绕过另一个模式的验证。

沿用 `comic_revisions` 与 `branch_comics`，不增加另一套作品表或把 JSON 放入 Quill。JSON 字段与验证的具体拆分由实现者确定，数据库或备份契约是否需升版根据实际持久化变化决定；新版本数据必须被不支持的读取方明确拒绝。

漫画 head 保存、恢复、分叉、删除、复制、备份、导入和同步都覆盖新来源引用及页资源。复制时区分全局的 revision／asset／task ID 与文档内 panel／page ID，重映射外部引用并重新计算指纹。导入严格检查两种来源和父版本链，不允许因为兼容 version 1 而放松 version 2 校验。

## 任务与失败恢复

在现有漫画任务增加原创规划、连续绘制和方向生成动作。原创规划与改编共用结构校验；原创检查剧情连续性及页／格／对白关系，改编额外检查原文忠实度。沿用现有最多一次自动修订；检查仍有问题时保存可编辑分镜并显示问题，不无限重试。

图像调用继续经过现有图片分类、供应商提示词转换、参考图、资源保存流程；为漫画保留页布局与文字要求，避免在通用提示词转换中重新被改成无字插画。现有单次图片数量、资源大小和取消限制保持有效。

规划、检查、图片子任务和接图逐阶段持久化。失败／关闭应用后恢复已有阶段和子任务；已完成页面不重复收费生成，状态未知的远端请求不盲目重发。取消传播到当前子任务；迟到图片保留资源但不覆盖已经变化的漫画。冲突结果可预览并保留，不能静默当作已写入。

新原创页面绘制完成才作为后续剧情依据。内部规划版本可保存在同一漫画历史中，但不会被方向生成误认为完成的页面。所有写入沿用比较当前 head 的事务保护，任务只跟进自己的保存版本。

## 助手能力

在 `EditorAgent` 准备阶段冻结当前漫画、焦点话／页及可见范围；在 `agent_runner.dart` 注册与执行漫画工具，调用同一 `ComicService`。不能复制一套只在聊天里生效的漫画流程。

工具能力包括读取当前漫画、创建／调整分镜、绘制已有分镜与按要求继续漫画。具体函数名由实现者确定；参数须明确目标章节与创作要求，执行时校验范围、目标 head 及图片归属。助手“给这一页出分镜”返回可编辑的已保存漫画版本；“按这个画”启动对应绘图任务，回复包含实际任务／版本结果。

原创漫画上下文以漫画为中心，不再注入空小说正文充当剧情；不提供生成小说正文或将插图插入正文的工具路径。通用作品信息、目录、资料和已有独立插图能力保留。小说助手继续保留现有工具，并可对所选原文调用漫画改编工具。

没有生图连接仍可出分镜；绘制工具缺少连接则返回可操作错误。仅要求分镜不会偷偷调用生图。作者明确要求绘制才进入现有生图授权流程；漫画工作区的“开始画／继续画”按钮本身是该次绘制请求，不再增加底稿审批步骤。助手若需现有图片确认卡，展示一次即可，不在每个内部阶段重复确认。

工具调用与子任务关系持久化，恢复不会把相同调用当作新请求。助手连续调用时只接受自身刚写入的漫画 head，不能吞掉用户同时编辑的结果；历史参考范围内修改、创建下一话和分叉沿用现有位置规则。

## 改动范围与验收

范围：创建表单和工作区、漫画编辑器／阅读器／请求入口、`ComicDocument` 与 store、`ComicService` 与 runner、方向界面、助手准备／工具执行、图片提示词接入、导出／快照与相关资料。现有小说生成、ST 编译和模型供应商协议保持原有行为。

核心验收使用本地协议服务器，不调用付费模型：

1. 正文一直为空的原创漫画，从一句开场完成分镜与图片保存；界面没有底稿入口，任务没有隐式小说生成调用。
2. 完成漫画得到恰好三个方向；选择其一只绘制一条路线；历史页与原图进入正确的上下文／参考图路径，未完成或过期内容不能进入续画。
3. 编辑、重画、章节顺序变化、历史恢复和并发调用使旧方向失效；旧任务结果不能覆盖新 head，取消与恢复不会重复创建已知图片请求。
4. 助手能在空原创作品保存分镜，也能绘制和继续；只出分镜时无图片调用；小说仍可忠实改编，原创没有原文证据要求。
5. 新图片内含完整对白要求；阅读与导出不重复外置文字；旧版内容无丢失，页资源在分叉、复制、备份和恢复后完整且归属有效。
6. 根包／核心包的针对性测试、分析和必要格式检查通过。宽窄布局、键盘／触屏入口与 16 像素内边距通过界面测试覆盖。

真实图片中文字准确性、角色视觉一致性及原生交互，需要真实模型／设备验证；本地模拟测试不能证明这些效果。实现交付时明确报告实际完成的验证，不沿用旧方案里上一次运行的通过记录。
