# 漫画创作与小说改编设计

日期：2026-11-07。状态：已实现，独立代码审阅问题已修复，全量本地回归通过；未提交。真实模型成图与原生交互尚未验证。

## 目标与已确认的方向

SillyDraft 同时支持小说和漫画。作者可以从故事想法创建漫画，也可以把已有小说按章节改编为漫画。两者最终都进入可编辑的分镜、逐格生图、纵向阅读和导出流程。

用户已确认的交互方向是：故事或章节 → 可编辑分镜 → 生图 → 漫画阅读与导出；支持分镜排序、单格重画，台词独立于图片编辑，复用角色参考图、生成记录和版本保护。

用户补充的核心要求是忠实改编：先提取小说中的基础信息，再转换成漫画能表达的形式。削减修辞不能削减剧情；动作、对白、心理变化、因果、伏笔和否定信息均须保留。最终漫画应能独立读懂，且不提前泄露后文。

以下数据结构、检查流程、默认条漫布局和导出格式是实现建议，并非用户指定的技术方案。

## 方案选择与范围

| 方案 | 得失 | 本设计的选择 |
| --- | --- | --- |
| 将小说交给生图模型直接画整页 | 流程短，但很难定位漏情节、修改台词、恢复失败进度，也不便控制阅读顺序 | 不采用 |
| 扩展现有“章节精彩瞬间”插图 | 可复用现有生图入口，但其 1–6 张精选规则会主动省略内容，不适合完整改编 | 只复用底层生图能力 |
| 独立保存事实与分镜，复用现有任务和插图服务 | 能追溯原文、编辑、检查和续跑；需要接入版本、备份和分支 | 采用，符合已确认的分镜创作方向 |

这是跨核心存储、任务、界面和迁移的功能。第一版完成原创漫画和小说改编的闭环，不建立专业自由排版器。

- 以章节为创作、检查和发布单位；可按现有分支顺序选取连续多章，顺序处理。
- 默认纵向单列，每格一幅静态画面，保持图片比例；台词、旁白在画面外的文字区呈现，支持姓名和类型标识。
- 提供离线 HTML ZIP 导出，包含完整图片和文字，可在浏览器连续阅读。
- 第一版不做动画、自由拖拽气泡、多格整页拼版、印刷排版或自动发布。
- 不限制改编只能产生 1–6 格；分镜数由情节和可读性决定，生图前显示实际数量。
- 不增加新的模型供应商、图片存储、后台任务系统或通用工作流框架。

失败判据包括：只生成剧情摘要、把比喻当实体、漏掉关键否定或伏笔、提前展示真相、对白说错人、改动原小说、重试悄悄重复付费、把有冲突的结果覆盖到作者正在编辑的版本。

## 创作入口

### 原创漫画

新建作品增加“小说 / 漫画”选择，旧作品默认小说。作品类型只决定默认入口和书架标识，不限制同一作品拥有两种表达形式。

漫画作品先有一份可编辑的“故事底稿”：作者可以自己写，也可以输入想法，由现有写作模型生成包含情节、人物、对白和结局的短底稿。底稿是正常章节正文，沿用写作任务与版本保护；无需先写成长篇小说。作者看过底稿后启动分镜生成。

故事底稿是原创漫画的内容依据。后续增加剧情先改底稿，再更新分镜，避免两份互不关联的故事事实。

### 小说改编

在工作区新增“漫画”区域，复用同一作品的资料、助手、插图库与章节选择。漫画区域提供“将本章改编为漫画”及连续章节选择。也可从小说章节菜单进入。

选定的是当前分支的正式章节版本，不读取阅读器显示正则生成的投影，不覆盖小说正文。界面同时显示小说版本、分镜版本以及是否已过期。

多章任务固定开始时的章节顺序和版本；一章未完成检查时不继续生成后章分镜，已完成章节可以先阅读。源章节被删、换序或改写时停止自动写入，保留任务结果供作者处理。

## 从原文到分镜

### 1. 冻结并切分源文

任务保存作品、分支、有序章节 ID 与 revision ID、正式正文、所用模型设置、画风要求、角色参考与截至当前位置的有效资料。内容来源和实际模型请求都可回查。小说和资料中的指令一律当作待改编内容，不赋予工具调用或改变任务规则的权限。

源文坐标基于冻结的 `ManuscriptContent.text`，使用 Dart UTF-16 偏移，保持原文字符，不先去修辞、改写标点或合并空白。切片不能截断代理对。正文附件位置单独记录，不能把 `\uFFFC` 当情节或静默删除。

程序按自然段、必要时按句子划分稳定的源文单元，再按模型上下文预算组合成批次。每个单元有独立 ID、章节 / revision ID、起止偏移与原文；纯空白可确定性跳过。任何含正文的单元都必须有处理记录。

批次留出系统提示、前情、结构化输出和检查结果的空间。不能用固定前 N 字或截断输出代替全文处理；单句过长可按完整字符继续分割。模型配置或供应商无法容纳最小批次时显示具体限制并停止，不以“已完成”跳过剩余文本。

普通 Markdown 只影响格式；未知 HTML、代码和嵌入内容明确列为待处理来源。可识别的展示代码 / 附件需说明处理方式，无法确定是否含剧情时阻止进入生图，并让作者整理成文字或明确确认其仅用于展示。此转换不改原始章节，处置记录属于本次改编。

### 2. 提取原始信息

文本模型按源文单元输出可追溯的事实，允许一个单元包含多个事实，或一个事实关联相邻单元。

| 信息 | 必须保留的内容 | 漫画表达原则 |
| --- | --- | --- |
| 动作 / 事件 | 谁、对谁 / 什么、做了什么、先后关系、结果 | 每格选一个时刻；连续动作拆格 |
| 对白 / 声音 | 说话者、原句、听者或声音来源 | 台词独立保存；无法确定说话者时标未知，不乱分配 |
| 心理 / 情绪 | 感受、认知变化、动机及程度 | 有原文依据的表情 / 动作，或简短旁白；不虚构内心台词 |
| 场景 / 状态 | 时地、人物位置、衣着、物品、伤势等变化 | 与上一格连续；改变必须有来源 |
| 因果 / 否定 | 为什么发生、没有发生什么、条件与限制 | 不把“没有开门”变成“开门”；原因不能省成突兀结果 |
| 线索 / 揭示 | 可见线索、读者何时知道什么、悬念 | 只画当时应呈现的事实，不提前给真相或结论 |
| 修辞 | 比喻所表达的事实、情绪或氛围 | 去掉字面意象，保留语义；没有额外语义的修饰可省 |

每条事实有稳定 ID、类型、主体 / 对象、朴素描述、来源单元与原文证据、叙述顺序、必要的前置事实 ID。否定、推测、回忆、梦境和不可靠叙述保留限定，不能升级成现实事实。

所有源文单元记录所提取的事实，或明确的“仅修饰 / 展示用途”原因。不能用“次要”“不适合画”豁免情节。后面的独立检查同时检查这些排除理由。

### 3. 转换为可画的分镜

分镜输出包括稳定 panel ID、关联事实 ID、场景 ID、出场人物、画面描述、构图 / 景别、人物与物品状态、对白 / 思想 / 旁白列表、必要的转场标识。

- 每格描述单一可画时刻。连续动作和不同时间不能塞进同一幅图，也不让模型自行拼小格。
- 台词默认保留原句和顺序，可以分到相邻格，不自动压缩、补台词或改变说话者。
- 心理变化若不能从表情可靠读出，用忠于原文的短旁白补足，避免要求图片表达不可见的复杂思想。
- 图像提示仅含画面、风格和必要的状态约束；完整台词由应用排版，要求模型不要绘制台词、文字框或字幕。
- 允许新增不携带剧情事实的构图与视觉设计；原文没定义的外貌可作为“视觉设定”提出并在生图前显示，不能伪装成原文事实。
- 一个事实可在多格表达，一格可承载多个同时发生且不矛盾的事实。所有剧情事实必须有明确承载位置。

### 4. 双层检查与有限修订

先做确定性校验：数据类型与版本、ID 唯一性、来源范围、事实引用、角色 / 资源归属、对白的文本和顺序、原文单元处置完整性、事实覆盖、依赖无环且不倒置。检查不能只看“覆盖率 100%”。

再单独调用文本模型，直接对照冻结的原文、事实和分镜，检查遗漏、虚构、因果断裂、否定丢失、说话者错误、修辞误译、剧透和阅读困难。检查调用不复用生成对话的推理结论；每个问题返回源文 / 事实 / 分镜位置与修正建议。

长章节按相同源文批次检查，包含相邻边界的原文和分镜，以及前情状态；跨批次的因果与转场另做边界检查。不能只拿事实摘要审事实摘要。完成状态要求所有批次、边界与结构检查结束，不能把未检查范围算作通过。

首次检查有问题时，最多自动修订一轮并重新检查。仍有问题则保存可编辑分镜与问题清单，状态为“需修订”，阻止生图。作者修改后可显式再次检查；没有无限自我修订或静默重试。

检查结果绑定源文版本和分镜内容指纹。作者改动事实、画面、台词、排序或删除格子后，旧检查立即失效；仅更换图片不改变文本覆盖检查，但会影响视觉连续性提示。

人工更改原文含义不会被记为“忠实改编通过”。第一版没有一键忽略所有遗漏的入口；需要更改故事时修改底稿 / 正文再改编。

“检查通过”表示结构检查和模型检查已通过，不承诺模型完全理解了原作。来源对照和人工预览始终保留。

## 连续性与揭示顺序

每批和每章结束保存连续性状态：当前时地、在场人物、固定外貌、当前服饰 / 伤势 / 持物、物品位置、读者已知信息、尚未揭示线索及对应来源。

- 场景未改变就沿用 scene ID；状态变化引用事实，不无故换装、换地点、移动道具或复活人物。
- 按原文叙述顺序改编，回忆、梦境、插叙加明确转场；不为了时间线“顺”而改成事件发生顺序。
- 基础资料取本分支前一章结束时的有效状态，本章新增信息只按源文揭示位置进入分镜。已有“本章总结”和本章后段生成的人物资料不能当作开场已知信息；现有按章查询的粒度不足以保证这一点，漫画上下文需额外过滤。不用后文解析或其他分支资料提前补真相。
- 从中间章节开始时，先从同分支前文生成仅用于连续性的文本状态，不生成前文图片。前文同样分批、有版本记录；已有有效状态可复用。开始前展示前情处理范围及额外文本调用。
- 角色参考图、场景文字状态和上一张同场景图共同约束生图。图像提供商支持参考图时沿用现有排序和数量限制；不支持时明确显示“仅使用文字设定”，不能冒称视觉一致性已保证。
- 更换较早的画面、参考图或视觉设定后，实际依赖它的后续画面标为“衔接待复核”。不自动收费重画，作者可查看后逐格重画。

## 生图、进度与恢复

生图前展示已通过检查的分镜、人物视觉设定、所用连接、分镜图片数、尚需创建的参考图数及已有完成数，一次确认启动本批。额外参考图生成须包含在已确认数量内；已有图片默认复用。

继续复用 `IllustrationService` 和现有 illustration 任务：内容分级、供应商提示词转换、参考图规划、实际图像调用、资源落盘与记录。每幅图片仍有现有的两次文本处理，不另起一套图片协议。

漫画任务依次提交和等待单格 illustration 子任务。每格保存子任务 ID、输入指纹、资源 ID、实际参考图 / 哈希和状态。完成一格立即持久化，不要求整个漫画成功才保存。图片进入现有插图库，漫画只引用同作品资源。

失败、取消或关闭应用后保留已完成格。失败即停，不自动重试付费图像请求；作者可“继续未完成部分”或“重画此格”。恢复先核对已有子任务和资源，完成的直接归位，尚在运行的接回原任务；远端结果不确定时提示状态未知，不创建重复请求。取消要传到当前子任务；取消后的迟到图片保留在插图库，不自动接到已修改的分镜。

文本提取、分镜、检查同样持久化阶段进度。恢复沿用冻结源文；源文已变则显示旧依据，不默默混入新版本。

任务管理不由页面生命周期承担。离开页面可继续，在任务页看阶段、当前章节 / 分镜、问题及恢复入口。

## 数据、版本与冲突

使用独立漫画文档，不将分镜 JSON 塞进 Quill，也不将正式作品内容塞进全局设置。

| 位置 | 内容与职责 |
| --- | --- |
| `novels.work_format` | `novel` / `comic`，默认 `novel`，决定默认创作入口 |
| `comic_revisions` | 不可变记录：id、novel_id、chapter_id、origin_branch_id、parent_revision_id、document_json、task_id、reason、created_at |
| `branch_comics` | 每个 branch_id / chapter_id 的当前 comic_revision_id |
| 版本化 `ComicDocument` JSON | 源文与前情版本、来源单元、事实、分镜、连续性状态、检查问题与绑定指纹、图片引用与生成状态 |
| 现有 generation_tasks / story_assets | 运行输入与恢复进度、模型请求结果、图片与历史，不复制图片字节 |

`ComicDocument` 从版本 1 起，严格校验必需字段、枚举、数量与长度上限、来源和引用。每次从源文重新改编创建一个 adaptation ID，分镜 / 事实 ID 在这次改编的编辑、检查、接图与恢复过程中保持稳定；它们是文档局部 ID，作品 / 章节 / revision / asset / task ID 是需重映射的外部引用，不能混淆。scene ID 由程序创建为唯一值，经连续性状态显式沿用到下一章，不用每章都从 `scene-1` 开始的名称猜测同一场景。

新增 `TaskKind.comic`，输入指定原文准备、分镜检查或生图阶段；由现有 TaskRunner 分派到漫画执行逻辑。模型连接复用现有写作 / 资料整理角色和生图选择；任务创建时解析出实际连接并冻结，不增加一组全局模型配置。具体类拆分留给实现者。

保存与接图都使用版本比较：校验源章节 revision、前情依据、当前漫画 head 与本格输入指纹。任一不匹配则不覆盖当前漫画，任务标“结果未写入”，保留完整文档 / 图片，提供预览、重新检查后应用或放弃入口。应用旧结果须基于最新 head 再生成 revision，不能绕过冲突检查。

生图逐格产生新漫画 revision，任务跟进自己的最新 head；作者同时编辑会阻止下一次自动接图。历史恢复也创建新 revision。源文改写后漫画标“依据已过期”，已有内容仍可读，不会反向覆盖小说或自动重新生图。

### 再次改编的明确边界

第一版采用整章重新生成候选，不做源文差异的语义匹配或自动三方合并。这是实现上的取舍，用于避免错误合并覆盖作者已改好的分镜。

- 当前漫画继续作为已保存版本。无论源文是否改变，点击“重新改编”都会生成新的 adaptation ID 和候选分镜，不直接替换当前 head，也不触发生图。
- 界面明确说明“将重新编排本章；当前漫画和图片保留在历史中，人工修改不会自动合入新分镜”。作者可以对照现有漫画与新候选，选择采用或放弃；采用时仍检查源文和 head 是否匹配。
- 新候选不会假定旧格与新格一一对应，不凭相似文字自动沿用图片。已生图片和参考图仍在插图库，作者可为新格选择已有图片；该关联保留来源并标记视觉衔接待复核。生成前显示实际缺图数量，已明确选择图片的格子不重复生成。
- 采用新候选创建以原 head 为父的漫画 revision，旧分镜、人工编辑和图片仍可恢复。同一次改编中的局部编辑和单格重画不走整章重新改编流程。

分支分叉复制截至分叉章节的漫画 head，沿用不可变历史和已有资源。分叉后编辑互不影响，不能带入分叉点之后的漫画或连续性资料。删除章节时清理该分支漫画 head，并遵循现有活动任务保护；其他分支与可引用历史仍完整。

## 迁移、备份与远程

- 数据库 schema 11 → 12：增加作品类型（默认小说）、漫画版本表与分支索引。旧作品、正文 revision 和图像引用保持不变；迁移在事务内完成。
- 备份升级到 `sillydraft-project` version 2 / schema 12，包含新列和漫画表。继续读取旧 version 1 / schema 9：先验证旧格式，再补默认值和空漫画表，规范化后执行严格列校验与关系校验；未知格式仍拒绝。
- 导出、恢复、复制、同步 fingerprint、归档 / 删除同时覆盖漫画数据。漫画图片、参考图和历史图片通过原有资源通道收集，不能只导出当前画面。
- 复制作品须显式重映射漫画中的外部 ID，包括源章节与 revision、前情、task、asset 和各分支 head。局部 panel / fact / scene ID 保持各文档内部关系；复制后重新计算绑定指纹，检查结果不能错误挂到另一个版本。
- 导入验证源文范围、事实 / 分镜关系、资源同作品归属、父版本链与 head 关系，拒绝缺少检查证据或指纹不匹配的通过状态、越界 / 孤立引用和未知文档版本；失败整体回滚，不部分覆盖作品。导入的模型检查记录注明来源于备份，它是历史记录，不是对检查真实性的密码学认证。
- 桌面远程作品库由主机迁移并执行漫画任务，手机沿用现有数据库通知与 TaskControl。旧客户端按现有同版本连接规则拒绝，不降级丢字段。
- 可选 `server/` 仍只执行客户端冻结的模型请求；不把小说改编语义搬到服务器。
- 作品备份格式和数据库版本是两个独立契约，更新对应 fixture 与兼容测试，不直接放宽旧格式的严格校验。

## 界面与导出

工作区新增漫画区域。宽屏可并排看分镜与原文，窄屏在分镜详情里切换；保留资料、助手、插图原有入口。使用现有 Forui 组件、响应式断点和间距规范。

分镜列表按阅读顺序显示缩略图 / 占位、画面描述、台词和检查状态；可新增、编辑、删除、上下移动。新增格也要关联事实并重新检查。详情可查看对应原文、事实、检查问题和生图记录，也可从现有插图库为该格选择图片。

主要操作随阶段显示：“生成分镜”“检查改编”“生成漫画”“继续未完成部分”“重画此格”“阅读”“导出”。问题应指出具体原文和分镜，不能只显示一个抽象覆盖分数。

阅读界面使用单列条漫，每格保留原图比例，文字区紧邻所属画面，按顺序显示姓名、台词 / 思想 / 旁白；中文长句自然换行，无固定行数裁剪。不把全部台词烧入图片，编辑文字后无需为排字重新生图。图像预留文本替代描述，所有操作有键盘和触屏入口；悬浮操作遵循现有 hover / focus / touch 规则。

第一版导出离线 HTML ZIP：一个入口页面、各章图片、独立文字、阅读顺序、作者标题信息及基本响应式样式。复用现有归档和文件保存边界，资源总量沿用 256 MB 上限，HTML 内容转义，不携带脚本、密钥、模型调试记录或小说全文。

导出选定的连续章节须全部有当前检查结果和完成图片；有缺格 / 未检查的章节明确列出并阻止“完整漫画”导出，不静默跳过。源文后来变化不删除旧漫画，作者可导出已完成的历史漫画，界面说明其依据版本。现有 TXT / Markdown / EPUB 小说导出继续导出正式小说；漫画入口明确标“漫画 HTML ZIP”，不暗中退回小说导出。

## 验收示例：修辞、因果和否定

原文：

> 听见门外的脚步声，阿宁把信塞进袖中。她的心像被冰水浇透，却仍笑着说：“我没见过那封信。”门外传来哥哥的声音：“开门。”她把手按在门闩上，没有拉开。

一种合格拆分（格数不是固定模板）：

1. 阿宁听到门外脚步声，侧耳，注意力转向门口。
2. 她将信藏进袖中；延续室内位置和服饰，道具去向明确。
3. 她强作笑容；可用简短旁白表达恐惧，台词为“我没见过那封信。”不能画冰水浇身。
4. 镜头保持门内，门外传来哥哥的“开门。”；声音来自门外，不提前让哥哥进屋，也不要求凭空补出外貌。
5. 阿宁的手按在门闩上，门仍关着；旁白可保留“她没有拉开。”以明确否定结果。

不得漏掉“听见脚步 → 藏信”的因果、信的位置、强笑与恐惧、两句对白的说话者及最后没有开门。不得擅加“不能被发现”等原文没有的心理台词。

## 验证与交付标准

测试全部使用本地协议服务器和固定图片，不调用付费模型。

1. 核心文档校验：UTF-16 / 中文 / emoji 范围、唯一 ID、无效来源、缺事实、跨作品图片、依赖环和未知版本均有明确错误。
2. 忠实改编：使用上述例子及否定、心理活动、隐喻、伏笔、插叙、未知说话者样本；验证任务输入包含保真约束、分阶段检查原文，缺项阻止生图。模拟模型不能证明真实模型永不漏情节。
3. 长篇：超过单次上下文仍逐批处理全部源文；批次边界的动作 / 对白 / 因果不丢失；截断、畸形 JSON 和缺失检查结果不能通过。
4. 连续性：中途开始、换装、受伤、物品转移、梦境回切、分支分叉与后文资料隔离；此前状态变化使后续依据过期。
5. 任务：阶段保存、逐格失败 / 取消、重启恢复、单格重画、未知远端结果、原文或分镜并发修改，检查已完成图片不被重复调用或覆盖。整章重新改编保留现有 head，候选采用 / 放弃、人工选图复用和旧版恢复均有覆盖。
6. 存储 / 迁移：数据库 11 → 12、旧备份恢复、新备份往返、作品复制 ID 与指纹重算、删除 / 历史 / 分叉、恶意或损坏导入回滚。
7. 远程：主机执行、远端读取进度、断线重连和漫画内容同步；可选执行器仍遵守冻结请求边界。
8. 导出：图片与台词顺序一致、中文不丢、内容转义、资源归属、体积限制、缺格阻止完成导出；旧小说导出回归。
9. 界面：小说 / 漫画入口、原文对照、编辑和排序后检查失效、冲突恢复、长台词、窄屏、键盘及触屏操作的 widget 测试。
10. 按项目要求运行 Dart / Flutter analyze、相关核心与界面测试、格式检查；如触及公共存储 / 任务契约再跑对应回归集。原生视觉验证和真实供应商效果单独标明，不用 mock 通过冒充已验证。

完成标准是作者能在界面中创建漫画、改编现有小说、定位并修正遗漏、连续生成并恢复进度、重画单格、阅读和导出完整漫画，且旧小说、分支、备份与远程作品库继续可用。
